---
id: maxConfidence
title: Highest-Confidence Window
---
**What it does.** Selects the single analysis window that reported the highest confidence and returns its BPM unchanged. Each analyzed window produces its own candidate list and a confidence score; _maxConfidence_ ignores the other windows and forwards the winner. It does not cluster or average tempos. The default merge strategy is now _windowVoting_ over selected rhythmic regions, so select _maxConfidence_ explicitly when you want this policy. It can also be combined with rhythmic regions, in which case the region selector still chooses the analysis spans but the final answer comes from just one of them.

**When to pick it.** Pick it when you trust one clean window more than agreement across windows, or to reproduce the historical behavior with _useRhythmicRegions_ disabled. For that historical result, choose both the legacy region setting and this merge strategy; changing only the merge policy still analyzes rhythmic regions, and changing only the region setting still votes on final BPMs from the old windows. This policy is useful as a control in paired benchmarks because its answer is traceable to one individual window without a consensus decision.

**Tradeoff.** A confidently wrong tempo can beat several quieter windows that agree on the correct tempo. _windowVoting_ uses their agreement; _maxConfidence_ does not. A strong half-time or double-time pulse can therefore produce an octave error even when other windows contain the annotated beat. Confidence describes the analyzer's internal evidence for one result; it does not measure whether that result matches the track's ground truth. On tracks with conflicting regional evidence, this policy offers no independent vote to correct an outlier. Compare against your own corpus before replacing the default voting path with it.
