title: Level 7: Default (full progressive)
---
**What it does.** Runs the _optimal_ technique set over three windows (30, 60, and 90 seconds) and merges them. It is the library's recommended default (aliased _default_) and the deepest DSP-only level: the full multi-window analysis the OA300 and GiantSteps accuracy floors are measured against. All three windows always run: the non-nil progressive threshold enables the multi-window path, and its numeric value (0.40) is currently a nil-versus-non-nil switch rather than a confidence gate. ComputeBudget fractions are reserved and uniform (_budget_ returns _ComputeBudget.default_), so level 7's advance over level 6 is the third 90-second window, not a budget change.

**When to pick it.** Choose it whenever accuracy is the priority and a few hundred milliseconds per track is acceptable: it is the setting the library's published accuracy numbers assume. It is DSP-only; every _EnsemblePolicy_ is coherent, with _dspOnly_ (the Options default) the natural pairing and the ML-invoking policies coherent but inert unless a technique is wired up. One source-code caution: because level 7 is aliased as _AnalysisIntensity.default_, a switch arm written as _case .default:_ matches _.level7_ through Swift's expression-pattern equality: it is not the bare _default:_ label and does not by itself make the switch exhaustive, so the other cases (or an actual fallthrough) are still required.

**Tradeoff.** Three windows cost the most of any DSP level, and running more of them does not guarantee a right answer: a consistent octave error that self-reports high confidence across all three windows survives the default maximum-confidence merge, so level 7 is not immune to the half or double failures that dominate tempo estimation; it only has more views to average over. And because levels 8-10 reuse this exact DSP path, raising intensity above 7 changes no DSP result today unless a future ML tier is wired.
