---
id: simpleMajority
title: Simple Majority Cluster
---
**What it does.** Resolves a window vote by picking the cluster containing the most windows, requiring at least two members to count as consensus. Ties on cluster size break first toward the cluster whose single strongest window has the higher confidence, then toward the cluster with the lowest original window index; within the winning cluster the highest-confidence window is returned. When no cluster reaches two members it falls back to _maxConfidence_ across all windows. This is the default _VotingPolicy_ and reproduces the established baseline byte-for-byte. The _votingThreshold_ option is ignored.

**When to pick it.** Use it, or leave it as the default, when you want window-count consensus with deterministic, well-defined tiebreaks and no tuning parameters. It is the right policy whenever a majority of windows agreeing on a tempo is the signal you trust, and it needs no configuration to behave predictably across runs. It is also the correct baseline to keep when comparing the other two policies, since any accuracy change they produce is measured against this one.

**Tradeoff.** Window count ignores confidence until the tiebreak, so a numerical majority wins even when the minority cluster has higher confidence: three low-confidence windows outvote two high-confidence ones. It also produces no consensus benefit when no cluster reaches two windows, with every window disagreeing or only one window present, collapsing to _maxConfidence_ and its over-confident-outlier weakness (an even 2-versus-2 split still elects a cluster by the confidence tiebreak; only a fully fragmented vote falls back). Where a 2-versus-1 split should sometimes favor the higher-confidence pair, _confidenceWeighted_ is the appropriate choice.
