## Successes

**S1. The library shipped as a product, not just a package.** Epic 4 shipped "infrastructure not accuracy." Epic 5 shipped a runnable consumer artifact: a sandboxed macOS app with a Liquid Glass icon, privacy manifest, App Store category, archive workflow, signed-build path, build-number bump enforcement, and a rename committed to its permanent App Store identity. The `.xcarchive` produced by `make demo-archive` is the first end-user-deliverable thing in this codebase's history.

**S2. Library accuracy floors held byte-identically across all 9 stories.** Every story's Completion Notes records `git diff --stat Sources/` empty + `git diff --stat Tests/` empty + OA300 + GiantSteps baselines verbatim from Epic 4 close-out. This is the strongest regression-protection backbone the project has ever had — the entire epic could be reverted and the library would behave identically. The discipline came from Story 5-1 DD #11 A3 (track wall-clock + invariant tests/baselines) carrying through every subsequent story.

**S3. Epic 4 retro A2 (deferred-work.md as canonical) worked exactly as designed.** 42 deferred sections across Epic 5; zero open `[ ]` checkboxes in story files. ## Key Insights

1. **The library is shippable as a product, not just a package — and these are different operations.** Library SPM consumers clone from `main`; App Store consumers download a `.xcarchive` built from `develop`. CLAUDE.md's "ships to main" table correctly excludes `Demo/`, but doesn't yet document this bifurcation explicitly. Should be added in Epic 5 retro carry-forward.

2. **Per-track impact reports remain mandatory, but Epic 5 didn't add any.** Epic 5 added zero accuracy-affecting code, so no per-track impact reports were warranted. This is a feature, not a bug — the discipline only fires when relevant. Future epics that touch accuracy should re-enable.

3. **`/bmad-party-mode` excels at scoping decisions; struggles with implementation decisions.** Story 5-4 Inspector reframe, Story 5-7 Liquid Glass mediation, Story 5-8 rename-scoping were all party-mode wins. Story 5-3's parameter-controls implementation (Slider binding, Picker change handler, Pasteboard write) didn't use party-mode — and didn't need it. Pattern: party-mode for "should we?" questions; single-LLM for "how exactly?"

4. **The Makefile-as-script-host has a ceiling, and `make demo-bump-build` hit it.** When a Makefile recipe acquires 3 rounds of code-review churn in <72h on the same dozen lines of shell pipeline, the right move is extraction to `uv run python scripts/<recipe>.py`. The Python form gives whitespace-tolerant regex, line-anchored substitution, count-verification, atomic file writes, and proper exception types. The Makefile target stays a one-line wrapper. Apply preemptively to future recipes approaching the same shape.

5. **Manual GUI smoke as a deferred operator-owned step is now project-standard rhythm.** Every demo-affecting story 5-2 → 5-7 closes with "AC #N manual GUI smoke pending user action — auto-mode cannot drive SwiftUI window-drop events." This is honest (the auto-mode dev agent genuinely can't drag files into SwiftUI windows) and stable (the operator runs the smoke at code-review time + commit time). Documenting this in CLAUDE.md as project-wide convention (replacing the "per Story 5-1+ precedent" pointer pattern) would close a discoverability gap.

6. **The 4-layer pre-PR + 1-layer post-PR review cadence is the new normal.** Codex MCP / Blind Hunter / Edge Case Hunter / Acceptance Auditor pre-push, GitHub Copilot post-push. Story 5-7 had FOUR nested review sub-sections because the cadence was applied repeatedly. The discipline catches real defects (`35F9.1` privacy reason, `Date()` ISO 8601 truncation, validateDropPayload URL guard) — but the documentation burden compounds. Should be documented in CLAUDE.md so the cadence isn't reconstructed from prior stories.

7. **Pre-1.0 framing absorbs the cosmetic naming mismatch comfortably.** Three coexisting names (`BoomBoomBoomKit` library, `BoomBoomBoom` product, `BoomBoomBoomKitDemo*` paths/scheme) inside one repo would be a clean-up flag if BC were a goal. Pre-1.0 it's a deferred cost the operator explicitly accepted. The library namespace is the load-bearing surface; the product name is operator-controlled. MediaDiff/MetaMan in production demonstrates the pattern is empirically livable.

8. **What Epic 5 actually shipped: 9 stories of developer-experience work, zero library code change.** This is the most extreme "infrastructure not source" epic in the project's history. Epics 1-3 changed `BPMAnalyzer`. Epic 4 changed Package.swift target structure + added 8 public types. Epic 5 added DocC + 17 CLAUDE.md entries + 80 demo tests + 1 demo app + 1 App Store submission cycle — and **modified zero lines of library DSP code, ML code, or test code outside the demo target**. The honesty of this close-out is that the library was production-ready at Epic 4 close-out; Epic 5 was about giving consumers (and one App Store) a way to see that.
