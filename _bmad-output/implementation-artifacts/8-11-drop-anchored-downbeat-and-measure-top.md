# Story 8.11: Drop-anchored downbeat / measure-top inference

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **beat-grid consumer needing bar-aligned (1/1, 1/2) quantization** (the Rekordbox-style DJ-sync app),
I want **the grid's downbeat / top-of-measure anchored to the track's main structural drop, selectable against the existing metrical-accent estimator**,
so that **bar-snap lands on the musically-correct downbeat instead of an arbitrary beat-phase guess — and I can pick (and benchmark) which downbeat strategy runs.**

## Context & why this story exists

Story 8.5a shipped the conservative, fixed-4/4, per-beat **metrical-accent** downbeat estimator (`DownbeatAnalyzer`): low-band/kick accent marks the bar start, with a 4-part abstain gate. Measured on the Rekordbox `Battito` downbeat oracle via the already-shipping `make benchmark-beatgrid` harness, it **fires on ~4.4 % of analyzable tracks** at **octave-tolerant correctness ~0.14** (constant-tempo subset; committed floor `downbeatCorrectnessFloor = 0.10`, `BeatGridBenchmarkTests.swift:474`). That is conservative by design — *a wrong downbeat on a live deck is worse than none* — but at a 4.4 % fire rate the feature is nearly inert on real material. **Story 8-5a-D1** (deferred-work `:836`) registered exactly this: a reported real-audio downbeat fire-rate / correctness metric, with the re-open trigger *"Story 8.5a lands the estimator."* That trigger is met; this story is the follow-up.

The dominant downbeat failure on EDM/dance material is that the per-beat metrical-accent heuristic rarely fires *and* is often wrong. A complementary, **structurally-grounded** evidence source — the track's main energy **drop**, which in dance music lands on a downbeat — places the bar phase more reliably than per-beat accent folding. The pipeline already contains a drop primitive: `BPMAnalyzer.findEnergyTransition` (`:1382`) scans 1-second RMS windows for the first significant energy step and is the analysis-window selector. This story generalizes that proven primitive into a **structural-drop downbeat estimator**, adds it as a **selectable strategy** beside the 8.5a estimator, and adds a **combiner** that cross-validates the two.

This is **pillar 2 of 3** in the beat-grid accuracy follow-up (operator decision 2026-06-23, `epics.md:1208`): **8-10** = continuous tempo refinement (`done`); **8-11** = this story (drop-anchored downbeat / measure-top); **8-12** = manual anchor reposition (`backlog`). It is downbeat **phase** placement (which beat-in-bar is beat 1) — the same `DownbeatResult.detected(estimate:)` + `gridOrigin.source == .downbeat` output as 8.5a — and it **does not touch BPM or the tempo octave**.

## Key Design Decisions (DD)

1. **Selectable strategy, not a replacement (operator decision 2026-06-28).** Add a public `DownbeatStrategy` enum — `.metricalAccent` (the verbatim 8.5a estimator), `.structuralDrop` (the new drop-anchored estimator), `.combined` (cross-validate both) — and `Options.downbeatStrategy: DownbeatStrategy = .metricalAccent`. The strategy is consulted **only when `detectDownbeats == true`** (the existing gate, default `false`). Default `.metricalAccent` reproduces the 8.5a path verbatim, so adding the enum is byte-identical for BOTH the default-off path AND the existing `detectDownbeats == true` path. `CaseIterable` (the benchmark + a future ablation enumerate it; `allCases.count == 3` unit-test-locked, mirroring `OctaveEquivalencePolicy`). It is **NOT** a `DSPTechnique` (no DSP changes, no ablation-matrix expansion) and **NOT** a `BPMSelectionPolicy`/`EnsemblePolicy` case. (This is the divergence from the 8.5a siblings `BeatGridAnchorSource`/`MeterSource`, which are deliberately NOT `CaseIterable` because no consumer enumerates them — here the harness does, so `CaseIterable` is justified.)

2. **Structural-drop estimator — reuse the in-repo drop primitive, but source it from the FULL pre-trim signal (the load-bearing correction).** ⚠️ **The analyzed span already starts at the drop.** `findEnergyTransition` (`BPMAnalyzer.swift:1382`) is the analysis-**window selector**: both the BPM path (`:282-288`, `analysisWindow = samples[dropOffset..<endSample]`) and the grid-coverage seam (`:641-658`, `coverageWindow = samples[dropOffset..<endSample]`; even `.fullTrack` is `samples[dropOffset..<end]`) slice the analyzed span to **begin at `dropOffset` = the first significant energy transition = the main drop**. A naive structural-drop estimator that scans "the grid coverage" therefore sees the main drop at frame 0 with **no preceding baseline to detect a step against**, and the phase fold relative to `beats[0]` returns a **tautological phase 0** (the window start was already aligned to the drop by `selectGridOrigin`). It would also get a genuine *interior* drop only on tracks where `findEnergyTransition` **failed** (returned `0`). The estimator must NOT consume the post-drop coverage curve. Instead:
   1. **Compute a sustained-LEVEL contour over the FULL pre-trim `decoded.samples` from file `t = 0`** (in scope at `BPMAnalyzer.swift:265`/`:627`, alive through both grid call sites) — NOT the drop-anchored coverage window (main drop would be at frame 0). The **primary** signal is a low-band RMS contour from a Float `vDSP.Biquad` low-pass (~150-200 Hz, kick+bass; the `LUFSAnalyzer.swift:255` biquad pattern but `ofType: Float.self`) — **NOT `subBands[0]`**, which is an onset-*flux* (transient) envelope computed on the post-drop window (wrong signal class AND wrong span; the Apple/Accelerate consult was explicit). A sustained drop is a *level* step, not a flux spike.
   2. **Multi-descriptor, not low-band-only (DnB requires it).** Low-band RMS alone is the least reliable cue on a breakbeat/DnB-dominant corpus (sub-bass / Reese sustains through breakdowns; the drop is often a rhythmic/timbral re-entry, not a clean low-band jump — Codex + Vande Veire & De Bie 2018). Score a drop from: bass-band RMS step **AND** broadband RMS step (full mix enters) **AND** a **high-frequency-flux / build-up penalty** that rejects risers (white-noise sweeps, snare rolls — rising highs with bass *absent* = build, not drop). The high-band discriminator may reuse the existing onset / `subBands` machinery (this is `subBands`' legitimate role — a secondary feature, not the primary level signal). Require pre/post **sustained** contrast (post-window elevated for ≥ 1-2 bars) and reject gradual ramps.
   3. **Novelty step detector, not a running-average threshold.** Replace `findEnergyTransition`'s first-crossing running-average threshold (`:1399-1403`, which false-fires on risers) with a **difference-of-boxcar-means** novelty curve (leading vs trailing window over the contour) — equivalently a short step/checkerboard kernel correlated along it (Foote 2000, a cheap 1-D novelty without materializing a self-similarity matrix). Peak-pick the dominant peak; this gives a cleaner abstain **margin** than a running-average delta. **(SHOULD: beat-synchronous aggregation** — sum/RMS the contour within each tracked beat before the novelty curve, per Zehren/Serrà — makes the drop land on a beat by construction and removes the window-left-edge bias for free, cheaper than a separate fine pass.)
   4. **Mandatory sub-beat localization + grid-constrained snap.** A whole-second RMS window (`findEnergyTransition`'s `windowSize = Int(sampleRate)`, `:1386`) spans ~2 beats at 128 BPM and reports the window **left edge** (`:1402`) → systematic off-by-one phase. Coarse-scan (~100-250 ms hop) then fine-refine (≤ `beatPeriod/8` or ~25-50 ms) around the candidate to **≤ `beatPeriod/4`** (parabolic vertex, `parabolicInterpolateACF` / `BeatGridAnalyzer.swift:679-692` precedent). Choose the **earliest sustained rising edge** whose post-window stays elevated; a flux/onset peak may *refine* an already-valid sustained step but must **never define** the drop — in DnB the loudest nearby onset is often a fill/crash/snare flam *before* beat 1 (off-by-one trap, Codex).
   5. **Candidates + runner-up margin (multiple drops).** Score all candidates from the full contour — `dropOffset` itself (`= windowStartSample`, the first re-entry, free) and any **later, more-prominent** post-breakdown drop. Take the dominant one; **abstain when the top-2 candidates imply different phases at similar confidence** (a double-drop / which-drop tie). Penalize early intro-only candidates unless interior-corroborated.
   6. Map the drop's **absolute file time** to the **nearest tracked beat** by file-relative `presentationTime` (`BeatGridAnalyzer.swift:321-322`); that beat's **position-quantized bar-phase** (`round((t − beats[0].presentationTime)/beatPeriod) % beatsPerBar`, 8.5a `DownbeatAnalyzer.swift:194-200`) is the downbeat phase (the drop-coincides-with-downbeat-of-phrase premise — Zehren & Alunno Rule 1; see Dev Notes literature grounding).
   7. **Abstain** (`.noneDetected`) on: weak margin; **off-grid** (> `beatPeriod/2` from any beat); **half-beat phase-ambiguous** (~equidistant from two adjacent beats); ⚠️ **half-BAR ambiguous** — confident only at the 2-beat (beat-1-vs-beat-3) level (the documented EDM failure: downbeat indistinguishable from beat 3 — Zehren & Alunno; an off-by-**2** that octave-tolerant scoring does NOT catch and ships a wrong downbeat). On the half-bar case, `.structuralDrop` standalone abstains; under `.combined` it emits a half-bar-resolution candidate and lets `.metricalAccent` break the 1-vs-3 tie (DD #3). Also abstain on `< 3` bars and the **degenerate window-start** case (only `dropOffset`, no interior corroboration).
   8. Emit the **existing** `DownbeatAnalyzer.Outcome` shape (`.detected(estimate: DownbeatEstimate, firstDownbeatBeatIndex:)` / `.noneDetected`, `DownbeatAnalyzer.swift:83-86`) → reuse `DownbeatEstimate` / `MeterEstimate { beatsPerBar: 4, source: .assumed }` / `BeatGridAnchorSource.downbeat`. **No new result types.**

   **Honest framing (v1) + named v2.** `.structuralDrop` is a **constraint-compatible single-to-few-feature novelty/homogeneity step detector**, deliberately abstain-heavy, standing in for the canonical multi-feature novelty-over-self-similarity-matrix SOTA (Yadati 2014's two-stage segmentation+classifier; Zehren & Alunno's Foote-checkerboard novelty). That trade is justified by the hard zero-dependency pure-Swift/Accelerate + no-ML constraint AND the "wrong-is-worse-than-none" posture (the literature itself documents drop detection as intrinsically imprecise — Yadati's 2.5 s avg boundary error — so aggressive abstention is the right hedge). **Deferred v2 (name it, don't build it):** Serrà-style structure features / Rocha-style timbral-SSM novelty as the principled non-ML upgrade if the DD #6 all-track-F gate underperforms.

   **Energy-signal sourcing (the real seam — more than "one param").** Threaded into `BeatGridAnalyzer.estimateBeatGrid` as a new parameter (the resolved absolute drop time + margin, or a `[Float]` contour + its sample-rate/hop) alongside `subBands`, computed at the `BPMAnalyzer` level where `samples` are in scope (`:565`/`:705`). The non-trivial work is NOT the param; it is **what contour to compute and how to re-map the absolute drop time into the file-relative grid** (steps 1-6). Keep the param defaulted so non-downbeat call sites are unaffected. vDSP primitive path in Dev Notes.

3. **`.combined` cross-validation — the usefulness lever, safety-preserving.** Run both estimators and combine by phase agreement:
   - **both fire AND agree** on the bar-phase → `.detected`, confidence **boosted** (the high-confidence sweet spot — two independent sources concur);
   - **both fire AND disagree** → `.noneDetected` (a phase conflict between two strong sources is a safety red flag — abstain, never guess);
   - **exactly one fires** → see the single-source rule below;
   - **`.structuralDrop` confident only at the half-BAR** (beat-1-vs-beat-3, DD #2 step 7) → `.metricalAccent`'s low-band accent breaks the 1-vs-3 tie; if `.metricalAccent` also can't resolve it, abstain. This is `.combined`'s most valuable distinct job: the drop nails the bar grid, the accent resolves the bar's *phase* — neither alone is reliable here, and the off-by-2 is the one octave-tolerant scoring will not catch;
   - **neither fires** → `.noneDetected`.

   **Single-source admission defaults to agreement-priority, NOT a blanket fire.** On this corpus `.metricalAccent` abstains on ~95.6 % of tracks, so "exactly one fires" is the *dominant* case and is almost always `.structuralDrop` alone — with no cross-check. Admitting every lone fire would ship a coarse/wrong drop phase as a confident downbeat on the majority of tracks (the precise "a wrong downbeat is worse than none" failure 8.5a exists to avoid). So at default, a lone `.structuralDrop` fire is admitted **only after measurement (AC #7) shows standalone `.structuralDrop` clears the raised correctness-when-fired safety floor**; until then `.combined` is agreement-priority (a lone metrical-accent fire is admitted — it is the conservative-proven path; a lone structural-drop fire abstains unless it passes a strict in-estimator confidence bar). The conflict-abstain and agreement-boost are **invariants**; the single-source-admission policy and the confidence blend are **measured tuning** recorded in Completion Notes (default toward maximizing the gated all-track F WITHOUT regressing correctness-when-fired). This is what the DD #6 all-track-F gate rewards and what a raw fire-rate floor would NOT (a raw floor rewards firing more, even wrongly).

4. **Stay out of octave / tempo arbitration — Epic 12 boundary (from the 2026-06-28 octave research, commit `db6fea4`).** The estimator places the downbeat **phase** on the grid the BPM stage produced, at *its* octave; it never re-picks the tempo octave (that stays the BPM stage's job, 8.10 DD #3). The octave investigation (`db6fea4`: `_bmad-output/implementation-artifacts/accuracy-ceiling-sweep-investigation.md`) proved every raw-periodicity octave-demote variant regresses both corpora and **redirected the octave lever to Epic 12**, endorsing *non-periodicity arbiters — perceptual ~120 BPM prior, **beat-grid coherence**, or a learned classifier*. Drop / measure-top structural evidence IS a beat-grid-coherence signal, so it is a natural FUTURE input to the Epic-12 octave arbiter — but **using it for octave selection is explicitly OUT OF SCOPE here** (note the seam in Dev Notes; do not build it). Downbeat scoring stays octave-tolerant (`BeatMatch.octaveTolerantF`, `BeatGridBenchmarkTests.swift:94`; the corpus is ~77 % half-time-tagged), so a correct phase on a half/double grid still scores. **Caveat (do not over-read the gate):** `octaveTolerantF` rescues the *score* (it max'es over downsample/upsample variants) but the emitted `DownbeatEstimate` still carries the BPM-stage octave's downbeat *density* — a double-time grid emits ~50 % spurious mid-bar downbeats, a half-time grid omits half the real ones. So a passing octave-tolerant usefulness gate does NOT guarantee a consumer receives bar-correct downbeats; consumer bar-snap correctness on wrong-octave grids is **bounded by the unfixed (Epic-12) octave problem**. DD #6 therefore also reports a strict (non-octave-tolerant) F to quantify how much "usefulness" is octave-masking vs consumer-real.

5. **Opt-in, byte-identical default; reuse the existing flag + estimator wiring.** No new `Bool`. `detectDownbeats == false` (default) → `DownbeatResult.notAttempted`, byte-identical to pre-story. `downbeatStrategy` defaults `.metricalAccent` → the `detectDownbeats == true` path is also byte-identical to 8.5a. Thread `downbeatStrategy` from `AudioAnalysisService.Options` (`:340`, beside `detectDownbeats`) → `BPMAnalyzer.Options` (`:231`) → BOTH `estimateBeatGrid` call sites (step-11 fan-out `BPMAnalyzer.swift:566`; `.window`/`.fullTrack` seam `:706`) → the downbeat branch in `BeatGridAnalyzer.estimateBeatGrid` (`:391`). **Threading trap (8.10 precedent):** the combined-path grid is built in `AudioAnalysisService.beatGrid(decoded:)` which constructs `BPMAnalyzer.Options` at two sites (`:1511`, `:1523`) — thread the strategy into BOTH or `analyze()` / `analyzeBeatGrid()` silently run the default strategy while `analyzeBPM` honors the override. Paired byte-identity opt-out test (default-off reproduces pre-8.5a; default-strategy reproduces 8.5a bit-for-bit), shared `static` helper, `Double.bitPattern`.

6. **Acceptance gate = a two-part safety+usefulness gate (Codex consult, thread `019f0ec0`, 2026-06-28), via the EXISTING harness.** The operator's instinct to *also gate fire-rate* is honored — but as the *all-track* yield metric, not raw fire-rate, because a raw fire-rate floor directly rewards weakening the abstain gate (the exact opposite of "a wrong downbeat is worse than none"). Extend `BeatGridBenchmarkTests` (Pass B already extrapolates downbeats and scores `octaveTolerantF`; writes `8-7-downbeat-accuracy.json`; gated by `make benchmark-beatgrid`):
   - **Safety gate** — `mean_downbeat_f_octave_constant` (octave-tolerant correctness **when fired**, constant-tempo) ≥ a floor **raised post-measurement** above today's `0.10` (target ≥ 0.15 if the measured `.combined` result supports it).
   - **Usefulness gate (NEW)** — an **all-track downbeat F**: octave-tolerant F over **every** analyzable constant-tempo track, with **abstaining tracks scored F = 0** (≈ `fireRate × correctnessWhenFired`, but computed directly per-track). Committed **post-measurement** at a floor materially above the 8.5a implied baseline (~0.006 = 0.044 × 0.14). This is the metric that proves the feature is *not inert* without the perverse incentive.
   - **Fire-rate** — **REPORTED**, plus a monotonic **not-below-the-8.5a-baseline** regression guard (NOT a usefulness gate; per 8-5a-D1 + the Codex adjudication).
   - **Per-strategy breakdown** — report `.metricalAccent` / `.structuralDrop` / `.combined` so the lift is attributable. **`.combined` beating `.metricalAccent`** is the goal, but it is **advisory until the first measurement**, NOT a hard gate at spec time — unlike the absolute post-measurement floors it is not self-calibrating, and the corpus is breakbeat/DnB-dominant (Dev Notes corpus reality), where the lift is genuinely uncertain. Promote it to a committed relative gate only once measured; route the final floor values through the open Codex thread `019f0ec0`.
   - **Strict (non-octave-tolerant) F + per-octave-band stratification — also reported (NEW, DD #4 caveat).** Emit a strict downbeat F alongside the octave-tolerant one, and stratify the per-strategy numbers by detected-vs-oracle tempo octave (or by BPM band: half-time ~80-89 vs full-tempo). Do NOT gate on the strict number (octave selection is Epic 12's job) — but the octave-tolerant-vs-strict gap quantifies how much gated "usefulness" is octave-masking vs consumer-real downbeats, so the operator does not over-read the octave-tolerant floor.
   - **Gate-vs-ship-path divergence — measured, not hidden (NEW, the critical mismatch).** The benchmark runs `beatGridCoverage = .fullTrack` (`BeatGridBenchmarkTests.swift:194`), but the **default** public coverage is `.analysisWindow` (`AudioAnalysisService.swift:326`) and the library docs steer sync-math consumers there (`AudioAnalysisService.swift:322-324`, `BeatGridCoverage.swift:18-19`). With the DD #2 fix (RMS contour over the full pre-trim samples, independent of `beatGridCoverage`), `.structuralDrop` is designed to work on the default path too — but that must be **proven, not assumed**: add a **second per-strategy REPORTING pass under default `.analysisWindow` coverage** to a NEW sibling `8-11-downbeat-strategy-accuracy.json` (kept separate from the calibrated Story-8.7 `8-7-downbeat-accuracy.json` so its F/correctness/drift gates are untouched; fire-rate + all-track-F), so default-path inertness is visible (the "if `.structuralDrop` fires 0 at default, say so honestly" Dev-Notes constraint, now wired to a number). It need not gate, but it must be recorded; if the two coverages diverge sharply, document the recommended coverage in DocC.
   - All committed floors are **post-measurement outputs** (8.10 DD #7 precedent): implement → run → record measured numbers in Completion Notes → THEN commit floors at (measured − margin). The octave-tolerant all-track-F aggregation reuses existing suite fields (`downbeatEvaluated` + `fired` + `octaveTolerantF`); the strict-F + per-band + default-coverage additions are new aggregations, not a new harness/oracle. Authoritative run is operator-owned (develop-only Tony corpus + Python `mir_eval` sidecar).

7. **Diagnostic evidence (typed, splittable).** Surface a typed `Sendable, CustomStringConvertible` evidence struct on `BPMDiagnosticTrace` (gated by `enableTrace`): strategy used, drop time, drop-derived phase, metrical-accent phase, agreement flag, chosen phase, confidence. ## Acceptance Criteria

1. `public enum DownbeatStrategy: Sendable, Hashable, Codable, CaseIterable { case metricalAccent; case structuralDrop; case combined }` is added (new file `DownbeatStrategy.swift` or co-located with `DownbeatEstimate.swift`); a unit test locks `allCases.count == 3` and the exhaustive `switch`. `Options.downbeatStrategy: DownbeatStrategy = .metricalAccent` is added to BOTH `AudioAnalysisService.Options` (`:340`, beside `detectDownbeats`) and `BPMAnalyzer.Options` (`:231`), threaded to BOTH `BeatGridAnalyzer.estimateBeatGrid` call sites (`BPMAnalyzer.swift:566`, `:706`) AND BOTH `BPMAnalyzer.Options` builds in `AudioAnalysisService.beatGrid(decoded:)` (`:1511`, `:1523`) (DD #1, #5).

2. **Byte-identical default + strategy-switch containment (paired opt-out test, shared `static` helper, `Double.bitPattern`):** (a) with `detectDownbeats == false` the full `BeatGrid` graph + `bpm`/`confidence`/`candidates` is bit-identical to the pre-story pipeline; (b) with `detectDownbeats == true` AND `downbeatStrategy == .metricalAccent` the output is bit-identical to the 8.5a path — asserted against an **independent stored 8.5a reference** (a committed bit-pattern snapshot captured at `baseline_commit`, or the pre-RMS-curve code path in the shared helper), NOT a second invocation of the same `.metricalAccent` dispatch (which would be near-circular). The claim is **OUTPUT** byte-identity only — the RMS contour adds *operations* on the `.metricalAccent` path, so this is not the `EnsemblePolicy.dspOnly` operation-inert standard; (c) **strategy-switch containment** — switching to `.structuralDrop` / `.combined` moves ONLY `downbeats` + `gridOrigin`; `bpm.bpm`, `confidence`, `candidates`, AND `beatGrid.estimatedTempo` stay bit-identical to the `.metricalAccent` run on the same fixture (test-locks the Epic-12 octave/tempo boundary, AC #5, at near-zero cost). The strategy is consulted only inside the `detectDownbeats` branch (DD #1, #5).

3. A `.structuralDrop` estimator detects the **dominant sustained drop** via a **novelty step detector** (difference-of-boxcar-means / Foote-style step-kernel correlation — NOT a running-average threshold, which false-fires on risers) over a **sustained-LEVEL contour computed from the full pre-trim `decoded.samples` (file `t = 0`)** — NOT the drop-anchored coverage window (`samples[dropOffset..<endSample]`, `BPMAnalyzer.swift:282-288`/`:641-658`, which puts the drop at frame 0). The primary signal is a low-band **`vDSP.Biquad` low-pass + RMS** (`LUFSAnalyzer.swift:255` pattern, `ofType: Float.self`), **NOT the `subBands[0]` flux envelope**; a **build-up/riser penalty** (high-band flux rising while bass is absent → build, not drop) + a pre/post sustained-contrast requirement reject false drops. It **localizes to ≤ `beatPeriod/4`** (coarse→fine + parabolic vertex, not the 1 s window left edge), the snap **refines** a sustained step but never **defines** it from the loudest nearby onset (DnB fill/snare-flam off-by-one trap), maps the drop's **absolute file time** to the nearest tracked beat's **position-quantized bar-phase** (8.5a `DownbeatAnalyzer.swift:194-200`), and emits the existing `DownbeatAnalyzer.Outcome` / `DownbeatEstimate` / `MeterEstimate(.assumed)` shape — **no new result types**. It abstains (`.noneDetected`) on: weak margin; **off-grid** (> `beatPeriod/2`); **half-beat phase-ambiguous**; **half-BAR ambiguous** (beat-1-vs-beat-3, the off-by-2 octave-tolerance misses — standalone abstains, `.combined` resolves via `.metricalAccent`); **runner-up tie** (top-2 candidates imply different phases at similar confidence); `< 3` bars; OR the **degenerate window-start** case. The contour/drop-time is threaded into `estimateBeatGrid` alongside `subBands` (DD #2).

4. `.combined` cross-validates: **agree → `.detected`** (boosted confidence), **conflict → `.noneDetected`**, **single-source → agreement-priority at default** (a lone `.metricalAccent` fire is admitted; a lone `.structuralDrop` fire abstains unless it clears a strict in-estimator confidence bar — blanket single-source admission is gated behind the AC #7 measurement showing standalone `.structuralDrop` clears the safety floor), **neither → `.noneDetected`**. Tests pin: two strong sources disagreeing never emit a downbeat; a lone coarse `.structuralDrop` fire does not ship a downbeat at default (DD #3).

5. A test confirms a half-time-seeded grid still receives the correct phase, and AC #2(c) test-locks that switching strategy never perturbs `estimatedTempo`/`bpm.bpm` (DD #4).

### Architecture note — `findEnergyTransition` already consumes the main drop (the audit's critical finding)

The pipeline's Step-1 energy scan IS the drop detector: `dropOffset = findEnergyTransition(samples:sampleRate:)` then `samples[dropOffset..<endSample]` in BOTH the BPM path (`BPMAnalyzer.swift:282-288`) and the grid-coverage seam (`:641-658`; `.fullTrack` = `samples[dropOffset..<end]`). ### vDSP implementation primitives (Apple/Accelerate consult, 2026-06-28)

Concrete Accelerate path — all reuse in-repo precedents, zero new dependency, no manual sample loops, exactly **one** new API family:

1. **Low-band level** — `vDSP.Biquad` Float 2nd-order low-pass (~150-200 Hz) over the full pre-trim mono `[Float]`, then RMS (`LUFSAnalyzer.swift:244-266` pattern, but `ofType: Float.self` — Float is fine here, gentle cutoff far from the unit circle, unlike K-weighting's near-pole shelves). `vDSP_desamp` (FIR LP + decimate) is an alternative. **Do NOT reuse `subBands[0]`** (flux, post-drop span).
2. **Contour** — `vDSP_rmsqv` per hop (generalize `findEnergyTransition`'s loop, `:1396`) OR the dense `vDSP_vsq` + `vDSP_vswsum` boxcar (the `adaptiveThreshold:2372-2389` precedent); choose hop ≤ `beatPeriod/4`. Stay in mean-square (skip `sqrt`) except to match the existing margin units.
3. **Step detector** — difference-of-boxcar-means: two `vDSP_vswsum` windows (leading/trailing), `vDSP_vsub` (**arg order is `(B, A, C)` → `C = A − B`**, flagged at `BPMAnalyzer.swift:978`), `vDSP_vthres` to keep rising edges (`adaptiveThreshold:2397`). A step matched-filter via `vDSP_conv` is the equivalent (correlation — **pre-orient the kernel**, `LUFSAnalyzer.swift:429`). A bare first-difference is wrong (fires on transients).
4. **Dominant step + margin** — `vDSP.indexOfMaximum` / `vDSP_maxvi` (value+index — the ONE new API; repo only uses value-only `vDSP_maxv`). Margin from `vDSP_meanv` baseline / second-best `vDSP_maxv`. Note: argmax returns first-on-ties → compare the two candidate margins explicitly (DD #2 step 5).
5. **Sub-beat refine** — guarded parabolic 3-point vertex (`parabolicInterpolateACF` `:1486-1497` / `BeatGridAnalyzer.swift:679-692`), scalar, no new API.

**Pitfalls:** Float sum-of-squares precision near silence (use Double for the contour if values sit near the floor — `LUFSAnalyzer.swift:245` precedent); `vDSP_vswsum`/`vswmax`/`conv`/`desamp` are LEFT-aligned and must NOT alias input==output (the left-alignment IS the window-edge bias — center-correct + rising-edge detect + parabolic refine); `vDSP_Length`/`vDSP_Stride` on all counts; guard non-finite/`< 2`-window and fall through to `.noneDetected` (never trap).
