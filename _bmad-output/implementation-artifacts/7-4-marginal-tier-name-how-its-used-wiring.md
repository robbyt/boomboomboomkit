### Design Decisions

**DD #1 — The "6 named fields / 5-signal vector" is partly aspirational; emit the schema honestly with two `null` columns; `idTagBPM` stays unwired (NOT mutagen) + a tracked deferred-work item.** The epic names `tonyLabel, dspBPM, rekordboxBPM, idTagBPM, gridBPM, duration-derived-BPM`. Reality: `tonyLabel = bpm_truth`, `dspBPM = signals.dsp.bpm`, `rekordboxBPM = signals.rekordbox_average.bpm`, `gridBPM = signals.grid_bpm.bpm` are real; **`idTagBPM` is structurally absent** (the `audio_metadata` labeler weight is 0.8 but `tony-tunes-labels.py:64` says "not yet wired" — no per-track key), and **`durationDerivedBPM` does not exist** (the survey has `total_time` but no derived-BPM signal anywhere; no producer in any planned story). Emit all six named fields for epic-schema fidelity, with `idTagBPM`/`durationDerivedBPM` = `null`, ALSO emit the four `*Relation` fields (the actual disagreement vector), and a top-level `_schemaNote` that distinguishes the two nulls precisely: `idTagBPM` = "producer exists (ID3 `TBPM`/`tmpo` via mutagen) but unwired — see deferred-work 7-4-D1"; `durationDerivedBPM` = "no producer in any planned story". **The idTag wire-vs-track fork is RESOLVED to keep-null + a numbered deferred-work item (Codex thread `019e8c00`, over John's wire recommendation):** (1) the categorization core MUST run corpus-free (JSON only); a mutagen pass needs the 241 files on disk, making a "dataset-side" categorizer host-dependent — the same fragility DD #5 has; (2) ID3 BPM is an explicit FR-15-forbidden MODEL input (`label-tier-policy-v1.md:103`), so even diagnostic use blurs a boundary the project keeps sharp; (3) the codebase already records structurally-absent signals as such (`grid_spacing` at `corpus_diagnostics.py:116`) — that is the consistent pattern.
