## How to read this

- Systems:
  - `boomboomboomkit-optimal`: AudioAnalysisService.analyze(url:) at default options (TechniqueSet.optimal); grid = beat-grid tempo extrapolated from gridOrigin.
  - `variant-joint-fit`: Story 15.7: DSP stub observations -> bar-state decode at the default BPM and the quarter level (the level the BPM stage chose; the fit never changes octave) -> joint tempo and phase fit, on the default pass's decode; a nil decode or fit abstains; the metrical-level selector's choice is recorded per row as a diagnostic only.
  - `variant-comb-best-phase`: Story 15.10 follow-up: the default grid re-anchored at the onset-comb best phase (internal BeatGridAnalyzer hook), observed on the default pass's decode; BPM answer unchanged from the default; refused per track when the observed run's output differs; runtime and memory not-comparable.
  - `variant-fixed-time`: Story 15.5 fixed-time model, BPM read from its scores files; tempo families only; Python inference, so runtime and memory are not-comparable with the Swift rows.
  - `commercial-analyzer`: a commercial DJ analyzer's BPM as recorded in the OA300 label file; version unrecorded, analysis mode unrecorded; no grid; OA300 only; a system under test, never the reference.
  - `oracle`: the corpus's independent reference.
- A pairing whose right-hand system is `oracle` is labelled system-vs-reference; every other pairing, including the library against `commercial-analyzer`, is system-vs-system. Agreement with `commercial-analyzer` says nothing about correctness.
- GiantSteps labels are crowdsourced; every GiantSteps pairing carries the tag crowdsourced-reference.
- Metric families stay separate. Strict tempo at [0.1, 0.05, 0.02] BPM; level classes within 4% of 1, 1/2, 2, 2/3 and 3/2; beat window 70 ms.
- Paired differences are a minus b. Interval: percentile 2.5 and 97.5 of the resampled statistic of paired differences: the median for continuous metrics, the mean for yes/no metrics, 10000 resamples, seed 20261030. p: scipy.stats.wilcoxon, two-sided, zero differences dropped for continuous metrics; exact McNemar from the discordant counts for yes/no metrics (downbeat_correct, failed_or_abstained, level_same, strict_0.02, strict_0.05, strict_0.10). Every p carries a Benjamini-Hochberg q-values over all tests in a corpus; each corpus states its test count.
- Accuracy rates and paired accuracy differences count an abstention or failure as incorrect; coverage is reported beside them.
- n is the paired count everywhere; n below 10 is underpowered and gets no direction. A direction is the sign of the paired difference's interval, stated only when paired n >= 10, interval excludes zero, q < 0.05, with its pairing, n, interval, p and q beside it.
- Families 4 to 7 (grid phase, beat precision, recall and F, downbeat phase, drift) need a reference annotation: a Story 15.8 hand annotation, or the planted click times of the synthetic corpus. A track without one reports no-reference and is left out of those pairings. Downbeat phase and drift are scored only when the grid is at the reference's tempo level (level-mismatch otherwise); drift is the grid's phase error at the last annotated bar line minus its phase error at the first.
- Memory: task_info TASK_VM_INFO phys_footprint, sampled every 1 ms on a second thread while each pass runs; value = high-water mark minus the footprint just before the pass.

## Limitations

- `commercial-analyzer` values exist for OA300 only, where the DAW-verified reference covers 22 tracks; most of its strata are underpowered.
- Its version and analysis mode were not recorded with the values; its grid is not available, so its grid families are no-data.
- `variant-fixed-time` runs in Python from a separate scoring run; its runtime and memory are not-comparable with the Swift rows. `variant-comb-best-phase` is the default analysis plus an observation; its runtime and memory are not-comparable too.
- The synthetic-clicks corpus is twelve clean click clips at one tempo; it measures grid timing on planted clicks, not on music.
- The 12.7 corpus carries no style tags.
