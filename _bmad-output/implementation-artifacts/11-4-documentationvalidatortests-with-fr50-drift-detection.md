> Capstone test-only story for the Epic 11 docs corpus. Stories 11.1–11.3b shipped the `DocumentedCase` protocol, the total-function `BoomBoomBoomKitDocs` accessor, and the 49-file canonical Markdown corpus across 10 enums. Because `.docs` is a TOTAL function that silently returns a fallback and `.inlineOnlyPreservingWhitespace` renders banned block markup as literal text, **a green build proves nothing about authoring correctness** — that is exactly what this story's authoritative validator proves, and what FR-50 drift detection enforces going forward. This story SUPERSEDES the three story-local guards (`DocumentedCaseAuthoredDocsTests` [11.3a], `DocumentedCaseAuthoredDocsTests11B` [11.3b], `RosterDriftCanaries` [11.3 follow-up]) with one cross-type validator + one drift-detection suite, and deletes them.

> Test-only + Makefile. No `Sources/` change (the 10 enums are already `DocumentedCase`-conformed from 11.2/11.3a/11.3b; the corpus already exists). Corpus accuracy floors are untouched (no DSP path change).

## Story

As a **maintainer guarding against documentation drift**,
I want **automated tests that fail if a `DocumentedCase` ships without a doc file, if a doc file has no matching case, or if any `.md` violates the KDD-E7/E8 authoring rules**,
so that **new cases cannot land without prose and no malformed Markdown reaches consumers via `AttributedString`.**

Deliverables: (1) an authoritative file-driven `DocumentationValidatorTests.swift` (per-rule + per-file axes, front-matter schema, render round-trip, scope discipline, word-count band); (2) FR-50 drift-detection suites in the existing `DocumentedCaseTests.swift` (one `@Suite` per documented type, case↔file bidirectional); (3) a `documentedKind`-directory registry cross-check so a new documented TYPE cannot ship un-validated; (4) deletion of the three superseded story-local guards, carrying forward their load-bearing content checks; (5) a `make docc-validate` target.

## Key Design Decisions

> **Finalized 2026-07-16.** Codex spec review (thread `019f6e07`) confirmed the factual core (iteration classes, payload types, protocol shape, corpus breakdown, the `DownbeatEstimate`-not-`[BeatTimestamp]` reconciliation) and drove 4 blocking + 6 should-fix amendments, all folded below: (B1) `Issue.record` defaults to a FAILING issue → the word-count/pressure-release soft band uses `Issue.record(_:severity: .warning)`, which is non-failing in this toolchain's Swift Testing (Swift 6.3.3, verified available); (B2) a no-`default:` switch forces a switch arm but cannot mechanically force the representative LIST to grow → DD-2 reframed to drop the false "CI necessarily stays broken" claim and keep the tripwire honestly as the strongest-available reminder; (B3) `swift test --filter` matches test/suite IDs, not filenames → the per-type drift suites nest under a parent `DocumentedCaseDriftTests` so the `docc-validate` filter can select them; (B4) DD-11 narrowed to a directory↔registry consistency check (it cannot discover a source conformer that ships with no directory). Should-fixes: strict visible-filename lock restored (a `_oops.md`/`.MD`/junk under a real type dir must still fail, not silently skip); CRLF/de-indent/≥20-words/word-boundary-lexicon promoted into the normative rule set; DD-10 corrected (`@Test(arguments:)` needs only `Sendable`, not `Codable`); corpus word range corrected to 218–299.

**DD-1 — `DocumentedCaseTests.swift` already exists (11.1); EXTEND it, do not recreate.** The epic AC ("Given `DocumentedCaseTests.swift` does not yet exist, When 11.4 lands, Then the file contains one `@Suite` per documented type…") is stale: Story 11.1 created this file with the accessor suite `@Suite("Story 11.1 DocumentedCase")` (protocol shape, sentinel happy-path, fallback, blank-parse, front-matter strip, split-extension, concurrency). 11.4 PRESERVES that suite verbatim and ADDS the per-type FR-50 drift suites to the same file, nested under one parent suite (DD-12: `DocumentedCaseDriftTests`, with one child `@Suite` per documented type) so a `--filter` can select them all. Flag the epic-text drift in the Change Log; do not touch the 11.1 suite's tests.

**DD-2 — FR-50 drift uses two mechanisms, split by iterability (verified against source); the compile tripwire is a forcing reminder, not a mechanical list-growth proof.** The 10 documented enums split into three iteration classes:
- **5 `CaseIterable` (free `allCases`):** `BPMSelectionPolicy`, `VotingPolicy`, `DSPTechnique`, `AnalysisIntensity`, `OctaveEquivalencePolicy`. Drift suite: `@Test(arguments: Type.allCases)` asserting `Type.<case>.docs` is non-fallback. Adding a case grows `allCases` → the parameterized test auto-covers it → CI fails (fallback) until the `.md` is authored. Fully **mechanical** runtime drift — `allCases` cannot silently omit a case.
- **1 with a hand-list (`EnsemblePolicy.allPolicies`):** not `CaseIterable` (assoc value on `.weightedVoting`), but ships `public static let allPolicies` (`EnsemblePolicy.swift:152`). Drift suite iterates `allPolicies`.
- **4 truly-manual assoc-value enums (no all-list):** `MLExecutionPolicy`, `DownbeatResult`, `AbstainReason`, `DemotionReason`. Each gets a hand-maintained representative `[Type]` list + a `@Test` iterating it asserting non-fallback. Representative values are lifted from the 11.3b suite (`mlCases`, `downbeatCases` with a `sampleEstimate: DownbeatEstimate`, `abstainCases`, `demotionCases`).
- **Compile tripwire for the 5 hand-rostered enums** (`EnsemblePolicy` + the 4): a no-`default:` exhaustive `switch` over the type in the test target, so adding a case fails the test-target BUILD. **Honest limit (Codex B2):** this forces a developer to add a switch ARM; it does NOT mechanically force them to also add the value to `allPolicies`/the representative list — a case added to source + switch but omitted from the list stays invisible to the runtime `.docs` check. Swift offers no way to enumerate a non-`CaseIterable` enum's cases at runtime, so this residual is inherent (the retired `RosterDriftCanaries` documented the same caveat). The tripwire is co-located with the representative list and a comment makes the coupling explicit; it is the strongest available reminder, not a proof. **Honest scope of the backstops (code-review correction):** if the omitted case ALSO has no `.md`, NO CI test catches it — the DD-9 file↔id check only fires on an ORPHAN or stale `.md` (a file present with no matching case), and DD-11 only catches directory-level drift; neither can inspect a case that has no file. That specific residual (case in source + switch, omitted from the list, no `.md` authored) is caught only by code review (deferred-work W84) and, at runtime, by the visible production fallback if code accesses the case. The DD-9 file↔id check and DD-11 DO backstop the more common shapes (an orphan/stale `.md`, a drifted directory), and the new per-type `documentationIDsAreUnique` check closes the duplicate-ID masking hole (a new case whose `documentationID` collides with an existing one).

**DD-3 — Supersede and DELETE the three story-local guards; carry their load-bearing checks forward.** `DocumentedCaseAuthoredDocsTests.swift` (11.3a, 13 `@Test`), `DocumentedCaseAuthoredDocsTests11B.swift` (11.3b, 23 `@Test`), and `RosterDriftCanaries.swift` (1 `@Test`) each self-document as living "until Story 11.4's drift validator lands." 11.4's cross-type validator + drift suites cover all 10 types generally, so all three are deleted. **Coverage must not regress on deletion** — these load-bearing checks migrate into 11.4's suites (not dropped):
- the strip-proof `.docs` assertion (non-empty, ≠ fallback, no `---`/`id:`/`title:`/`payload:` token in the render) → the FR-50 drift `.docs` assertion;
- the exact 49-file corpus total → a corpus-count `@Test` in `DocumentationValidatorTests`;
- the **strict, case-sensitive per-type filename lock** (Codex should-fix #1): per real type dir, the exact set of visible files must equal `{<id>.md}` — a stray `BPMSelectionPolicy/_oops.md`, a `.MD` extension typo, or non-`.md` junk under a real type dir FAILS (it must not be silently skipped). The `_`-stem skip (DD-5) applies only to CONTENT validation of the `_Fixture/` sentinels; the filename lock still fails a `_`-prefixed file that appears under a real type directory;
- payload-invariant `documentationID` (assoc-value cases proven with ≥2 distinct payloads) → a drift-suite `@Test`;
- the 11.3b targeted semantic checks — `level7.md` `.default`/`~=`/exhaustivity footgun; every `levelN.md` budget-honesty (`budget` + one of {reserved, uniform, 1.0}); `*Reason/sourceSpecific.md` no phantom double-quoted string — migrate into a `DocumentationContentChecksTests` section (type-specific; NOT expressible by the generic file rules).
- **Intentionally retired (Codex nit #2):** the per-story exact 24-file subtotal and exact source-order roster-ordering assertions are superseded by the per-type bidirectional set-equality against the live registry (DD-4/DD-9) + the 49-corpus total; AC-11's "coverage preserved" scopes to structural/content checks, not those per-story-count artifacts.

**DD-4 — The file-driven validator is SOURCE-linked, not re-rostered.** The "id matches a real case on the type named by the parent directory" check and the bidirectional case↔file drift consume ONE canonical `[documentationID]` per type, derived from the live enums (`allCases`/`allPolicies`/the DD-2 manual lists), NOT a re-typed stem literal — surfaced as a `kind → [id]` dictionary (`[String: [String]]`) plus a `kind → (stem → payloadType)` map (`[String: [String: String]]`), both built from the concrete per-type lists. The drift suites and the file validator therefore share one source of truth and cannot disagree about a type's real cases.

**DD-5 — Validator scope (Paige #6), proven with a temp fixture (no junk shipped).** The content-validation collector = `Sources/BoomBoomBoomKit/Resources/Documentation/<Type>/*.md`, ONE level deep, EXCLUDING `_`-prefixed DIRECTORIES (so `_Fixture/` is skipped wholesale — cleaner than relying on per-file `_` stems, and future-proof against a hypothetical `_Fixture/notUnderscored.md`; Codex should-fix #5) and EXCLUDING `_`-prefixed file stems, and NEVER descending to `Resources/*.md` (where `README.md` — which legitimately has headings — and `_template.md` live; both OUT of scope). The dedicated `validatorScopeRespectsReadmeAndTemplates` `@Test` proves the filter in isolation by building a TEMPORARY directory tree containing (a) a deliberately-invalid `<Type>/_test.md` (heading + table + code fence), (b) a `README.md` with headings at the resource root, AND (c) a **positive in-scope control** `<Type>/valid.md` — then asserting the collector returns the control and NOT the other two (the positive control prevents a wrong-root collector from passing vacuously). It ALSO asserts the real on-disk collection excludes `README.md`, `_template.md`, and the entire `_Fixture/` directory, and that validating the real collection passes. The strict filename lock (DD-3) is a SEPARATE per-type check that still fails a `_oops.md`/`.MD`/junk placed under a real type dir.

**DD-6 — Word-count policy is the AC band; the soft band is a non-failing `.warning`.** Hard-FAIL a body outside `100...600` words. Inside `100...199` or `401...600`, emit `Issue.record(_ comment, severity: .warning)` — which records a NON-failing issue in this toolchain's Swift Testing (Swift 6.3.3; default `.error` severity is what fails, so the existing repo `Issue.record(...)` calls fail by design — Codex B1). The dev-story MUST verify at build time that a `.warning`-severity issue does not fail the test (place one warning-band fixture and confirm the suite stays green); if the toolchain ever regressed this, fall back to a plain `print`-prefixed warning (never a failure). This authoritative policy replaces the retired story-local hard 200-400. The shipped corpus measures **218–299** words per file (Codex-corrected) → all inside the non-warning 200–400 core, so zero warnings at ship.

**DD-7 — Render round-trip through the real path.** Each in-scope file is front-matter-stripped (mirroring the accessor's `strippingFrontMatter`) then parsed via `AttributedString(markdown: body, options: .init(interpretedSyntax: .inlineOnlyPreservingWhitespace))`, and the result asserted non-empty by the ACCESSOR's own definition (`BoomBoomBoomKitDocs.swift:123`) — contains ≥1 non-whitespace character (not merely `!isEmpty`, which whitespace-only bodies pass under inline-only mode). Catches malformed Markdown the static checks miss. **Pressure-release valve (epic AC):** if `AttributedString(markdown:)` flakiness surfaces on specific punctuation, downgrade ONLY this render `@Test` to a non-failing `Issue.record(_:severity: .warning)` (structural checks stay fatal) and document the deviation in `_bmad-output/implementation-artifacts/11-4-pressure-release.md`. Not expected to fire; the accessor already round-trips all 49 files in production.

**DD-8 — Two `@Test` axes so a failure isolates BOTH file and rule; the exact `Rule` set is locked; markup scan is single-line-enforced.** `DocumentationValidatorTests` runs a single `validate(file) -> [Problem]` core (each `Problem` tagged with a `Rule`) across BOTH axes: (a) one `@Test` PER `Rule` case, scanning every in-scope file and reporting which files violate that one rule; (b) one parameterized `@Test(arguments: inScopeFiles)` — a single declaration expanding to one test case per file — running all rules on each file. Same core, so the axes cannot diverge. **Markup-scan soundness (code-review resolution):** the core FIRST enforces one physical line per paragraph (`paragraphSingleLine` — the corpus convention), which makes scanning EVERY body line for block markup sound: a valid file has no continuation lines, so the scan can neither false-positive on a hard-wrapped line nor false-NEGATIVE on markup a continuation would otherwise hide. The normative 18-case `Rule` enumeration: `frontMatterSchema` (DD-9), `fencedCode` (```` ``` ````/`~~~`), `indentedCode` (tab or 4-space lead, non-blank), `table` (a GFM delimiter row — NOT a bare pipe count, which false-positived on `|x|`), `image` (`![`), `link` (`](`, `<scheme:…>` autolinks incl. `tel:`/`urn:`/`mailto:`, and `<user@host>` email autolinks), `inlineBacktickOrDocLink` (`` ` `` or `<doc:`), `atxHeading` (`^#{1,6}(\s|$)` after ≤3 leading spaces — NOT `#1`), `setextHeadingRule` (`^(=+|-+)$`), `blockquote` (leading `>`, with or without a space), `listMarker` (`^[-*+](\s|$)` / ordered `^[0-9]+[.)](\s|$)`), `fileSize` (≤ 10 KB), `threeOrderedBoldLeads` (exactly `**What it does.**` → `**When to pick it.**` → `**Tradeoff.**`, each appearing exactly once, in order), `paragraphHasProse` (each of the 3 paragraphs ≥ 20 words), `paragraphSingleLine` (each paragraph is exactly one physical line), `tradeoffFailureSignal` (Tradeoff matches the word-boundary failure lexicon — targeted `mis*` stems, not the bare `mis` that matched "mission"), `wordCountBand` (DD-6), `renderRoundTrip` (DD-7, incl. the pure-CR front-matter-strip-divergence catch). The core normalizes CRLF→LF for the structural checks; the render round-trip deliberately strips from the RAW content to mirror the accessor exactly.

**DD-9 — Front-matter schema validation (KDD-E7).** Per file: a well-formed `---`…`---` block (present, terminated); required `id` and non-empty `title`; every non-blank block line is `key: value` (no duplicate keys); `id` == filename stem; `id` == a real `documentationID` on the type named by the parent directory (via the DD-4 registry — this is the file→case direction of the bidirectional drift; the case→file direction is the DD-3 filename lock + the DD-2 drift suites); `payload` present IFF the case carries an associated value, equal to the expected type, and matching `^[A-Za-z_][A-Za-z0-9_.]*$` (a Swift type identifier). Expected payloads (source-verified): `EnsemblePolicy/weightedVoting → SignalWeights`, `MLExecutionPolicy/whenDSPConfidenceBelow → Double`, `DownbeatResult/detected → DownbeatEstimate` (source truth — NOT the epic's stale `[BeatTimestamp]`), `AbstainReason/sourceSpecific → String`, `DemotionReason/sourceSpecific → String`; ABSENT on every other case.

**DD-10 — Per-concrete-type suites for readability + the epic's wording (NOT a compilation necessity).** Codex should-fix #3: `@Test(arguments:)` requires only that arguments are `Sendable` — NOT `Codable`/`CustomTestArgumentEncodable` (the repo already parameterizes over `EnsemblePolicy`, which is neither, in the 11.3a suite). All 10 documented types and their representative values are `Sendable` (verified: the 5 CaseIterable enums, `EnsemblePolicy`, `MLExecutionPolicy`, `AbstainReason`, `DemotionReason`, and `DownbeatResult`/`DownbeatEstimate` all conform), so any of them is a valid `@Test(arguments:)` element. The drift suites are written PER CONCRETE TYPE purely because (a) it matches the epic AC's "one `@Suite` per documented type" wording and (b) a concrete-typed parameterized test gives a cleaner failure label than an erased `any DocumentedCase`. The FILE validator parameterizes over `URL`/`String` file paths (both `Sendable`) and maps parent-directory name → expected ids via the DD-4 dictionaries. No existential is ever an `arguments:` element.

**DD-11 — Directory↔registry consistency check (narrowed claim).** `documentedKindDirectoriesMatchValidatedTypes` asserts the set of non-`_`-prefixed `<Type>/` directories under `Documentation/` EQUALS the set of `kind` names the validator registry knows about: a `Documentation/NewType/` dir with no registry entry → fail; a registry entry with no dir → fail. **Honest limit (Codex B4):** this is a directory↔registry check, NOT a source-conformer inventory — it CANNOT detect a brand-new `DocumentedCase` conformer that ships with no directory at all (or an `_`-prefixed one), because Swift has no runtime "all types conforming to protocol X" reflection here. That residual is caught only by the code-review checklist and by the fact that an undocumented conformer returns the visible fallback in production. The check still closes the real, common drift (a doc directory added/renamed out of sync with the validator).

**DD-12 — `make docc-validate` target with a filter that actually selects the drift suites (epics.md:187).** Add a `docc-validate` Makefile target running the authoritative suites independently. Because `swift test --filter` matches test/suite IDs (a regex), NOT source filenames (Codex B3), the target uses three `--filter` regexes (union): `--filter BoomBoomBoomKitTests.DocumentationValidatorTests --filter BoomBoomBoomKitTests.DocumentationContentChecksTests --filter BoomBoomBoomKitTests.DocumentedCaseDriftTests` — the last selects the parent drift suite and its 10 nested per-type children (whose test IDs contain the parent name). The dev-story MUST verify the filter actually selects the drift suites (run the target, confirm the per-type drift tests execute — a filter that silently matches nothing is the failure mode here). Makefile ships to main; the target is consumer-runnable (pure `swift test`), so no `ml-*` fail-loud guard. Documented in `make help`.
