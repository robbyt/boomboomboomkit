# Story 8.2: Shared-decode wiring — three analyzers consume one `DecodedAudio`

Status: ready-for-dev

## Spec validation history

- **2026-06-10 — factual-claims grep (mandatory pre-spec).** Six epic-AC errors/gaps found against the live codebase:
  1. **`PCMBufferReader.read(url:)` does not exist.** The decode entry is `readMonoSamples(from:maxSeconds:targetSampleRate:) throws -> (samples: [Float], sampleRate: Double)` (`PCMBufferReader.swift:50`). All decode-counter language in this spec targets the real method.
  2. **Epic AC6 is factually impossible as written** — "`BPMAnalyzer`, `LUFSAnalyzer`, and a placeholder `BeatGridAnalyzer` stub all receive identical `OnsetFeatures`". `LUFSAnalyzer` never consumes `OnsetFeatures` (it K-weights raw samples; no mel/onset stage). Reinterpreted in AC4: all three consume the SAME `DecodedAudio`; `OnsetFeatures` byte-identity applies to the onset consumers only.
  3. **Epic AC2's "typically a `DecodedAudio` accessor on `BPMDiagnosticTrace` plus a `decodeOnce` parameter on the service Options struct" — both rejected** (DD #1): embedding multi-MB PCM in every `Sendable` trace snapshot is a memory disaster with no consumer; an Options-level decode-override closure is a DI seam nothing needs.
  4. **`OnsetFeaturesBuilder.build` has ZERO production call sites.** Story 6.2 DD #8 shipped the Tier-1 facade only. The Tier-3 dependency inversion is NOT this story — Story 8.4's step-11 insertion owns it (DD #6).
  5. **`BPMAnalyzer.estimateBPM(samples:sampleRate:options:)` has ~40+ call sites across 9 test/benchmark files** — see DD #4 for the migration (operator-directed full removal, no shim).
  6. **`FeatureSubstrate.DecodedAudio` is MONO by KDD-S2** (`samples: [Float]`, init precondition `sampleRate >= 8_000`). The 8-1-D1/D4 "per-channel carrier lands in 8.2" trigger language was aspirational — re-deferred with corrected triggers (DD #11).
- **2026-06-10 — pre-implementation review round (Codex thread 019eb349 + axiom platform consult + party-mode panel Winston/Amelia/Siri/John, real subagents) + operator decisions.** Headline outcomes, all folded into the DDs below:
  - **Operator directive: NO backwards-compatible cruft.** The v1.0 spec's shim-retention DDs are overruled — `estimateBPM(samples:sampleRate:options:)` and `measureLoudness(samples:sampleRate:)` are REMOVED; all call sites migrate (DD #4/#5, two-commit strategy).
  - **Codex CRITICAL + unanimous panel: the epic's ≥35% perf gate dies.** Asserted with no measured decode-vs-DSP budget; arithmetic (saving = D/(2D+B+L)) makes it codec/intensity-dependent and likely unreachable at intensity 7. Replaced by probe-first + structural gate + probe-derived floor (DD #10, operator choice "Probe + structural gate").
  - **Codex MAJOR: byte-identity claims overstated; "lossless containers" sloppy** (CAF/AIFF-C can carry lossy codecs). Axiom + Siri: Apple documents NO bit-stability for `AVAudioFile` reads; LPCM prefix-reads are structurally stateless (safe to test-lock, no-SRC carve-out); FLAC decode is bit-exact BY FORMAT SPEC → belongs in the bitPattern set. All byte-identity language reframed to LPCM-payload + FLAC named-fixture regression locks (DD #3a).
  - **Codex MAJOR: DD #2 equality contract missed trace/ML/progress divergences** (`durationHintDetail` writes below the 180s gate at `BPMAnalyzer.swift:2503`; internal ML-trace construction at `AudioAnalysisService.swift:331` even when `enableTrace == false`). Rewritten: equality is structural (url path IS the funnel) + result-level under pinned options; trace comparison is whitelist-only (DD #2).
  - **Codex MAJOR + Amelia: the `onDecode` hook leaves the Options structs entirely** — internal `decodeObserver` parameter design (DD #9). Counter pattern: `Mutex<Int>` (Synchronization, macOS 15+); `Mutex` is `~Copyable` → box in a `final class …: Sendable` probe.
  - **Siri: extension-derived codec tagging indefensible** (.m4a can be ALAC; .caf can carry AAC); `audioFile.fileFormat.streamDescription.pointee.mFormatID` is the content-true codec for free (NOT `processingFormat` — that's the decoded PCM side). **Operator choice: reshape `AudioCodec` to codec semantics** (DD #7).
  - **Siri: AVAudioFile already trims declared priming** (packet table: CAF `pakt`, MP4 edit info, LAME/Xing) before samples are visible — but headerless ADTS/MP3 leak encoder delay undetectably, so zero-trims must mean "applied-or-unknown", never "known zero". **Operator choice: PrimingInfo gains explicit trim-state provenance now** (DD #7a; resolves W63 by removal).
  - Codex: new public `readDecodedAudio` would inherit the reader's unsanitized `maxSeconds` `Int64` trap (`PCMBufferReader.swift:95`) → producer sanitizes (DD #3b). AC6 count-lock → set-equality test. AC5 cancellation wording tightened (DD #8).

## Story

As a library consumer,
I want `analyzeBPM` and `analyzeLUFS` (and the forthcoming `analyzeBeatGrid`) to share a single decode pass via public `DecodedAudio`-accepting overloads on `AudioAnalysisService`,
so that combined analysis never pays for the same decode twice (FR-35, structural), and the KDD-C4 seam is in place before Story 8.4's step-11 insertion and any unified `analyze(...)` follow-up.

## Key Design Decisions

1. **The seam is DecodedAudio-accepting overloads + one public producer; combined `analyze(...)` stays deferred (KDD-C4 verbatim).** New/changed public surface, exhaustively enumerated (Mary's seam rule — this IS the PR-description promotion list):
   - `PCMBufferReader.readDecodedAudio(from:maxSeconds:) throws -> FeatureSubstrate.DecodedAudio` — public producer; wraps `readMonoSamples` + codec tagging (DD #7) + trim-state (DD #7a) + `maxSeconds` sanitization (DD #3b).
   - `AudioAnalysisService.analyzeBPM(decoded:options:) throws -> AudioAnalysisResult?` and `analyzeLUFS(decoded:options:) throws -> LUFSReport?`.
   - `LUFSOptions.isCancelled` (DD #8).
   - `FeatureSubstrate.AudioCodec` RESHAPED to codec semantics (DD #7) and `FeatureSubstrate.PrimingInfo` RESHAPED with `TrimState` (DD #7a) — both pre-1.0 breaks with zero existing consumers (verified: nothing in Sources/ constructs either outside tests; zero `AudioCodec` test references).
   - `DecodedAudio.synthetic(_:sampleRate:)` test-construction helper — public, in `BoomBoomBoomKitTestSupport` (NOT the library target).
   - First-production-consumer DocC + README for `DecodedAudio`/`PrimingInfo`/`AudioCodec` (the Epic 6 ↔ 8 seam promotion this story owes).
   Internal (NOT public): `decodeOnce` funnel + `decodeObserver` parameter (DD #9), the `BeatGridAnalyzer` stub (DD #6). REMOVED (internal, no public impact): `estimateBPM(samples:sampleRate:options:)`, `measureLoudness(samples:sampleRate:)` (DD #4/#5). Rejected: `BPMDiagnosticTrace` DecodedAudio accessor; Options-level decode closure; `onDecode` fields on Options structs.
2. **The url path IS the funnel — equality is structural, then verified at the result level.** `analyzeBPM(url:options:)` is reimplemented as: URL-bound signal gathering (metadata read, `fileDuration(url:)`) + `decodeOnce` + the SAME shared core that `analyzeBPM(decoded:options:)` calls. One code path; the DD #2 divergence class (trace writes, ML-trace construction, progress ordering) becomes shared behavior, not a reconciliation burden. URL-bound signals on the decoded path: metadata corroboration absent (no URL → `FileMetadataReader` can never run), `fileDurationSeconds = nil` (no derivation from `samples.count` — wrong under a capped decode; the hint is a URL-bound signal, documented). Verification tests:
   - Result-level equality (lossless per DD #3a): `bpm`/`confidence` bitPattern + element-wise `candidates`, decoded-path vs url-path under PINNED options: `metadataPolicy = .disabled`, `durationHint = false`, `ensemblePolicy = .dspOnly`, `enableMLDiagnostics = false`.
   - Trace comparison is FIELD-WHITELIST only (decode-invariant fields) — never whole-trace `==`; `durationHintDetail`/ML-trace internals are excluded with a comment citing `BPMAnalyzer.swift:2503` / `AudioAnalysisService.swift:331`.
   - One divergence-by-design lock: tagged fixture, DEFAULT `metadataPolicy` — url path corroborates (`metadataEvidence` non-empty), decoded path doesn't (`metadataEvidence` empty); both asserted explicitly so nobody "fixes" the divergence later.
3. **Byte-identity discipline (3a) + `maxSeconds` semantics (3b).**
   - **3a.** All bitPattern assertions run on LPCM-payload fixtures (`test-bwf.wav`, `test-bwf.caf` — verified LPCM — AIFF) + FLAC (bit-exact by format spec; the only Apple-owned step is the deterministic int→Float32 scale). AAC/MP3 are tolerance-or-excluded (8-1 measured ~1e-7 same-machine AAC drift). Carve-outs stated in test comments AND DocC: the locked path has NO sample-rate conversion (SRC is stateful; capped-vs-full reads may legitimately differ at the cap boundary under SRC), and claims are "verified by regression tests on LPCM/FLAC fixtures", NEVER "guaranteed by the platform" (Apple documents no bit-stability contract for `AVAudioFile`). The phrase "lossless containers" is banned from spec/tests/docs — gate fixture membership on payload codec.
   - **3b.** Decoded overloads apply their Options' `maxSeconds` as a prefix-slice mirroring the reader's cap arithmetic exactly (`min(AVAudioFrameCount(clamping: Int64(sampleRate * maxSeconds)), totalFrames)` — `PCMBufferReader.swift:95-96`). The 8-1 sanitize rule (finite, > 0, < 1e9, else nil = full file) is extracted to ONE shared internal helper and applied at all three entry points: `readDecodedAudio` (the new public producer must not inherit the `Int64(Double)` trap), `analyzeLUFS` (both paths), and the BPM decoded overload's slice. Negative-path tests at each.
4. **`estimateBPM(samples:sampleRate:options:)` is REMOVED — full migration, two-commit strategy (operator no-cruft directive).** `estimateBPM(decoded:options:)` is the only entry. All ~40+ call sites across the 9 test/benchmark files migrate via `DecodedAudio.synthetic(_:sampleRate:)` (TestSupport helper pinning `.linearPCM` + `.knownNone` — tests never hand-pick provenance).
   - **Commit 1 (mechanical, inert):** add the helper + migrate every call site + the analyzer signature swap, ZERO behavioral change. Full suite + all four corpus floors green BEFORE the seam work starts. Any test that flips here is a finding, not a flake.
   - **Commit 2+:** the seam work lands on the locked baseline.
   - **Pre-migration failure-mode audit:** `DecodedAudio.init` has a `precondition(sampleRate >= 8_000)` — grep the 9 files for `sampleRate:` literals < 8000 and degenerate-input negative tests BEFORE migrating; rewrite those explicitly against the precondition contract (a trap is not a nil).
   - **Provenance-invariance test (new):** same samples, two different codec tags → bitPattern-equal `BPMResult`. `DecodedAudio` is a carrier; nothing downstream may branch on provenance fields.
5. **`LUFSAnalyzer` migrates the same way — and analyzers still never throw.** `measureLoudness(decoded:)` is the only entry; old form removed; same two-commit discipline (the lock: `LUFSByteIdentityTests` UNTOUCHED and green). Unsupported-rate handling stays EXACTLY where it is today: the SERVICE throws `LUFSAnalysisError.unsupportedSampleRate` before calling the analyzer; the analyzer returns nil on missing K-weighting coefficients (project rule: never add `throws` to analyzers — panel suggestion to throw from the analyzer is rejected on this rule). New test: direct analyzer call with an 8 kHz `DecodedAudio` → nil; service decoded overload with the same → throws.
6. **Tier-3 inversion is NOT this story; the beat-grid placeholder is an internal stub.** Story 6.2 DD #8's Tier-1 facade stands. New internal caseless enum `BeatGridAnalyzer`, single member `static func onsetFeatures(for decoded: DecodedAudio, weighting: WeightingProfile) throws -> OnsetFeatures` calling the builder, marked `// Story 8.4 placeholder: real beat-tracking replaces this`. Its assertable invariant IS AC4(b) (bit-equal `OnsetFeatures`) — it is not behaviorless scaffolding.
7. **Codec tagging is content-derived via `fileFormat` mFormatID — `AudioCodec` reshaped to codec semantics (operator-approved pre-1.0 break).** Cases: `.linearPCM, .aac, .alac, .mp3, .flac, .unknown` (`String, Sendable, Hashable, CaseIterable, Codable`; container names .wav/.aiff/.caf are DELETED — they were containers, not codecs, and `PrimingInfo.codec` is about codec priming). `readDecodedAudio` switches on `audioFile.fileFormat.streamDescription.pointee.mFormatID` (`kAudioFormatLinearPCM`, `kAudioFormatMPEG4AAC`, `kAudioFormatAppleLossless`, `kAudioFormatMPEGLayer3`, `kAudioFormatFLAC`, default → `.unknown`). NOTE for dev: `fileFormat` = encoded on-disk format; `processingFormat` = decoded PCM — using the latter would tag everything `.linearPCM`. Invariant test is SET-equality (`Set(AudioCodec.allCases) == [.linearPCM, .aac, .alac, .mp3, .flac, .unknown]`), not count (count passes when a case is swapped). This resolves ALAC-in-.m4a / AAC-in-.caf / compressed-AIFF-C mis-tagging by construction; no extension parsing anywhere.
8. **(7a) `PrimingInfo` reshaped: explicit trim-state provenance, no magic zeros (operator-approved).** `PrimingInfo` becomes `{ codec: AudioCodec, trimState: TrimState }` with `public enum FeatureSubstrate.TrimState: Sendable, Hashable, Codable { case knownNone; case unknown }`. The `leadingTrimFrames`/`trailingTrimFrames` Int fields are DELETED — nothing can populate them honestly in 8.2 (AVAudioFile pre-trims declared priming; undeclared priming is invisible without the C-level `kAudioFilePropertyPacketTableInfo` query, which is Story 8.5's job and lands as an additive `TrimState` case, e.g. `.declared(leadingFrames:trailingFrames:)`). Population rule: `mFormatID == kAudioFormatLinearPCM` → `.knownNone` (LPCM has no priming concept); everything else → `.unknown` ("trim already applied by the decoder, or leaked undetectably — caller must not assume either"). DocC states this verbatim. **Resolves deferred W63 by removal** (the unvalidated Int fields no longer exist).
9. **LUFS cooperative cancellation lands here (resolves deferred 8-1-D2).** `LUFSOptions.isCancelled: @Sendable () -> Bool = { Task.isCancelled }` (exact mirror of the BPM Options field). Check points, exhaustively: url path — before decode (throws with decode count 0) and after decode / before measurement; decoded path — before measurement. SERVICE-LEVEL ONLY — no per-block checks inside `LUFSAnalyzer` (analyzers never throw; an in-flight measurement runs to completion — O(n) vDSP, documented granularity, same ADR-1 rationale as BPM's between-windows-only). `readDecodedAudio` does NOT check cancellation (documented explicitly — it's a plain throwing reader call, same contract as `readMonoSamples`).
10. **(9a) Decode-observer seam: internal `decodeObserver` parameter — public Options structs untouched.** `decodeOnce(url:maxSeconds:isCancelled:observer:)` internal, observer default nil, fired once per actual decode. Internal overloads `analyzeBPM(url:options:decodeObserver:)` / `analyzeLUFS(url:options:decodeObserver:)` thread it; the public methods pass nil. Tests reach the seam via `@testable import`. Counter pattern (Axiom-confirmed): `Mutex<Int>` from Synchronization (macOS 15+); `Mutex` is `~Copyable` so an escaping `@Sendable` closure boxes it in a `final class DecodeProbe: Sendable`. The observer payload is the produced `DecodedAudio` (lets tests assert `samples.count` for slice checks). Decoded overloads cannot decode by construction (no URL parameter) — the type system is the proof; no hook needed there.
11. **(10) Perf: probe FIRST, structural gate HARD, floor probe-derived (operator-approved; replaces the epic's ≥35%).**
    - **T0 probe (BEFORE seam implementation):** measure median decode time D vs analysis time per format on OA300 ({MP3, FLAC, WAV-class} × default intensity, matched `maxSeconds = 120`), release config, ≥3 warmups, randomized file order, median-of-N — record per-format D-share in the Debug Log. ~Half-day cap.
    - **Hard gate 1 (structural, the FR-35 promise, HALT-worthy):** decode fires exactly once per analysis on every path (AC1) — deterministic, never flaky.
    - **Hard gate 2 (directional):** combined shared-path wall-clock ≤ sequential wall-clock per format, within measurement noise — the seam may never make things slower.
    - **Probe-derived floor (reported + gated):** achieved saving (sequential − shared) ≥ 0.8 × measured single-decode cost D_f for the decode-heavy formats (MP3, FLAC). WAV-class is reported only (decode-trivial; noise-dominated). Secondary informational number at library defaults (BPM 120s / LUFS full-file) reported honestly, labeled secondary — no cherry-picking the matched-window number as the headline.
    - Emitted to `_bmad-output/implementation-artifacts/8-2-shared-decode-impact.json` `{perFormat: {sequentialMedian, sharedMedian, decodeMedian, achievedSaving, floorMet}, defaultsConfig: {...}}` via env-gated benchmark test + `make shared-decode-impact-report`. HALT only on gate 1; floor misses surface as findings with the probe data attached.
    - **epics.md Story 8.2 perf AC is PATCHED in this PR** to this formulation (the 35% was asserted, not derived — Codex CRITICAL, panel unanimous).
12. **(11) Deferred-work dispositions.** RESOLVES: 8-1-D2 (DD #9), W63 (by removal, DD #8/7a).
