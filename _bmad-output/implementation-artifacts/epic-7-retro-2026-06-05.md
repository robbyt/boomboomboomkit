## Challenges

**C1. (SYSTEMIC) Fail-open guards on non-finite / partial / empty inputs were the dominant defect class — 5+ stories, one shape.** A guard that defaults to pass/true/bundle when the input is degenerate: NaN escaping a clamp (7.5 `_octave_fold` +inf hang; clamp-must-follow-isFinite); a count gate ignoring its denominator so a partial corpus passes (7.6 `>55/82` on 56/56; 7.7 per-corpus); an aggregate proving net-benefit with zero comparable corpora (7.7 FR-24, convergent BLOCKER); JSON writers emitting `Infinity` (7.5 `build_marginal_stability`); signoff guards failing OPEN on ambiguous marker counts (7.4). This is the ML-harness analog of Epic 6's NaN-Hashable trap and warrants the same treatment: a named discipline + a mechanical check, not per-story reviewer memory. → Action **A1**.

**C2. "Done" overclaims relative to the operator-gated deliverable.** All 7 stories are `done`, but the authoritative FR-18/FR-25/FR-24 numbers and the bundle-vs-BYOW decision do not exist — they gate on the still-pending KDD-B4 signoff. The stories are legitimately complete *as harnesses* (7.5 DD #16), but sprint-status carries no asterisk and the epic's actual outcome is unproduced. Resolved this retro by **holding the retrospective open** with explicit close conditions rather than recording a clean close. → "Held-Open Close Conditions."

**C3. Signal-independence circularity recurred three times.** 7.2: `analyzeBPM` returns the post-corroboration BPM (and `0.03` matches the corroboration default), so a naive DSP-vs-tag gate is self-fulfilling → fixed with metadata-BLIND DSP + independent `mutagen` tags. 7.6: the `.mlOnly` `result.bpm` fallthrough (DD #12). 7.7: the calibration input↔output loop (DD #14). Same root cause each time: *a metric silently reading a contaminated or fallback signal looks clean but is wrong.* Worth naming as a standing review lens.

**C4. Smoke/parity fixtures were too weak to catch real-audio bugs — twice, same root.** 7.3 (MPS int64) and 7.5 (float32 accumulation) both passed their CPU/short-fixture checks while a real-audio/real-device bug lurked. The reusable lesson: any parity or smoke harness for a transform that runs on long tracks or on-device MUST include a long-track and/or on-device signal, or it is structurally blind to the most likely failure.

**C5. Epic spec text was partly aspirational and corrected at dev time in every story.** The "5-signal disagreement vector" (7.4 — only 3 BPM-bearing signals exist), the named `non-rekordbox/` input dir (7.2 — derived, doesn't exist), the parity seam (7.5), the `1e-6` tolerance (7.5 — float STFT/log accumulation cannot hold it end-to-end; aligned to the 1e-4/1e-3 harness floor). Caught by the factual-claims grep each time, but the spec-ahead-of-reality drift is a recurring tax.

**C6. Tony's long DJ tracks broke timing/memory assumptions.** 7.3 smoke wall-time was preload-dominated by Tony's 4-6 min tracks (`--subset 32` blew the <2 min AC1 target → fell back to `--subset 8`); the full run was "days-not-hours + OOM-prone" (~250 GB pretrain preload) until PCM-windowing + lazy datasets landed. The original targets assumed GiantSteps-length tracks.

## Key Insights

1. **Fail-open is a defect *class*, not a set of incidents** — it has one shape (guard defaults to pass on degenerate input) and deserves one systemic countermeasure (rule + mechanical test), exactly as NaN-Hashable did in Epic 6.
2. **An operator-gated epic should close on the operator run, not on the harness.** Marking the epic done when the harness ships (but the promotion decision is unproduced) is the same fallback-signal trap the epic spent itself catching, turned on our own process.
3. **Long-track + on-device smoke is non-optional for transforms that run long or on-device.** Short synthetic fixtures are structurally blind to accumulation drift and device round-trips.
4. **Signal-independence is a first-class review lens.** Before trusting a gate/metric, ask: can the number it reads silently fall through to a contaminated or fallback signal? If yes, bind to the un-contaminated source explicitly.
5. **Independent consult pays for itself on novel arithmetic and load-bearing forks.** Both the KDD-B2 confound fix (strong-only) and the calibration circularity resolution (downgrade-only DAG) came from outside the author.
6. **The factual-claims grep is load-bearing and cheap.** It caught reality-deltas in all 7 stories; skipping it would have shipped specs written against false premises.

## Close-Out Addendum (2026-06-09) — BYOW

The operator run completed. The authoritative outcome the epic was built to compute now exists, and it is **BYOW**: the v2 model is not good enough to bundle.

### What was run
- **KDD-B4 corpus signoff: SIGNED.** `corpus-diagnostics-v1.md REVIEWER_SIGNOFF: signed`; `audit-corpus-splits.py --check-gate` passes. Corpus grew to 1,534 tracks (Strong 523) after two hand-label ingest batches (+90, then +190; 120-140-BPM-weighted), drift snapshot 0.
- **Training: `maskedMelPretrain` seed-42 + tempo-band rebalance**, the KDD-B2 winner, on the 191-hand-label corpus. Best val_acc1 0.648.
- **FR-18 (gate b/c, the load-bearing gates), `.mlOnly` runtime, real numbers:**
  | corpus | result | gate | verdict |
  |---|---|---|---|
  | OA300 | 43/82 (52.4%) | > 55/82 | FAIL |
  | GiantSteps | 348/661 (52.6%) | ≥ 537/661 | FAIL |
  Both fail by a wide margin (~12 pts / ~189 tracks). **Decision: BYOW.** FR-20 freeze stamped `epic7CloseDecision="byow"` into the seed-42 metadata + training_log.

### Close conditions consciously WAIVED (honest disclosure)
The original held-open conditions asked for *multi-seed* training and FR-25/FR-24 numbers. We closed without them, deliberately:
1. **Single-seed, not the 42/43/44 matrix.** A double-fail by ~12 pts / ~189 tracks does not need 3-seed dispersion — dispersion only disambiguates a result *near* the gate. Documented so this does not read as "the full matrix failed"; it reads as "one seed failed so far past the bar that more seeds cannot rescue it."
2. **FR-24 net-benefit NOT run.** It requires a matched two-arm pair (maskedMelPretrain + supervisedAugmented) on the *same* corpus/split. The `supervisedAugmented` arm on disk is a **stale earlier snapshot** (corpusHash `2294f44a` vs the 191-track `25e59a18`; splitHash differs) — not comparable. No matched pair exists; FR-24 is structurally un-runnable here. The downgrade-only DAG means it could only have confirmed BYOW anyway.
3. **FR-25 calibration / holdout-gap / post-bundle-watchlist NOT run.** No-ops: the decision DAG is monotone-downgrade-only and FR-18 already landed on BYOW; these can only confirm, never promote. Skipped to avoid characterizing a model we are not shipping.

### The root-cause finding (carry-forward to the model-quality epic)
Three retrains (baseline 296 / +90 330 / +190 348 GiantSteps) proved the failure is **structural, not data-volume**. A zero-compute octave-tolerant re-score (E0) split the sub-120 dead zone into two causes:
- **<100 BPM = clean octave-doubling** — 38/60 predict *exactly* 2× truth; octave-tolerant Acc2 65% vs Acc1 2%. Decode-fixable without retrain.
- **100-120 BPM = genuinely mis-pulsed** — Acc2 == Acc1 == 1/35; representation problem.
Octave-perfect ceiling is 401/661; the gate (537) needs an input-representation fix too. **FR-16 (octave-aware loss) was delivered and the model still doubles** — the failure lives below the loss function, in the fixed 30/60/90s-window→512-frame representation (smears slow tempo) and the naive `30+argmax` decode. Full writeup: `_bmad-output/ml-training/v2-runs/octave-bias-finding-and-plan.md`.

### Carry-forward
The model-quality fix (octave-aware decode → input-representation redesign → octave-aware training → bigger model on the Apple Neural Engine) is **out of Epic 7's scope and in no existing epic**. It is chartered as **Epic 12** (see `epics.md`), sequenced *after* Epic 8 (whose ModelRegistry is the distribution channel and whose beat-grid is an independent octave cross-check). The bigger-model training run is gated on the representation redesign landing first — a bigger model on the current representation only gets "more confidently wrong."
