## Story

**As a** demo user evaluating BoomBoomBoomKit's beat-grid output,
**I want** a horizontal timeline showing beats and downbeats with a current-time scrubber driven by real audio playback, alongside a labeled text readout — and a switch to flip between this new view and the existing waveform view,
**So that** I can watch the grid track the audio as it plays and read the tempo / beat-count / downbeat / confidence numbers without inspecting JSON, without losing the richer waveform inspection surface.

This is a **demo-only** story (`Demo/BoomBoomBoomBPM/`, develop-only). `Sources/` and `Tests/` MUST stay byte-identical. It consumes the Epic 8 public surface (`BeatGrid`, `BeatTimestamp`, `DownbeatResult`, `DownbeatEstimate`, `TempoAgreement`) already flowing into the demo via `AudioAnalysisService.analyze(...)`. **Two operator decisions taken at spec time (2026-07-10) expand the epic AC:** (1) the new timeline is added *alongside* the existing Epic-8 `BeatGridView` behind a user-facing view-mode switch — the old view is NOT thrown away; (2) the scrubber tracks **real `AVAudioPlayer` playback**, so this story introduces the demo's first audio-playback substrate. The design was hardened by a pre-dev Codex review (thread `019f4f14`) — see the Change Log; its headline fix is the long-lived security scope (DD5).

## Acceptance Criteria

**AC1 — Canvas timeline (waveform-free).**
**Given** a tracked result (`GridVisualizationState`, whose `beatGrid` comes from `CombinedAnalysisResult.beatGrid` via `analyze(...)` — **not** a field on `AudioAnalysisResult`, DD1),
**When** `Demo/BoomBoomBoomBPM/BoomBoomBoomBPM/BeatGridTimelineView.swift` renders,
**Then** it uses SwiftUI `Canvas` (KDD-D2 — not `Path`-in-`ZStack`, not Metal, not `NSView` bridging) to draw one vertical tick per `beatGrid.beats` `BeatTimestamp` (DD4 — raw detected beats, the literal AC), visually-distinguished **taller** marks at **every `DownbeatEstimate.beats` timestamp** of a `.detected` downbeat result (DD4 — the payload's beat times ARE the downbeat markers; not derived from `phaseIndex`/meter), and a distinct anchor marker at `beatGrid.gridOrigin?.presentationTime` when present. Empty `beats` and a `nil` anchor draw only the static baseline frame (no failure); a tick whose time is outside `[0, span]` is **omitted** (not piled at an edge), while the scrubber alone is clamped (AC2/DD6).

**AC2 — playback scrubber via `TimelineView(.animation)`.**
**Given** the timeline is visible and the user starts playback,
**When** playback time advances,
**Then** a vertical scrubber line tracks the `PlaybackController` (real `AVAudioPlayer`, DD5) current time across the Canvas via **display-driven `TimelineView(.animation)`** — **NOT** `Timer`-driven `@State` mutation — updating as fast as the display refreshes while playing. The **static** tick/downbeat/anchor layer is drawn ONCE outside the `TimelineView` closure; only the scrubber lives in the animated subtree (DD6/#10). The scrubber x is clamped within the Canvas bounds `[0, width]` even if `currentTime` momentarily exceeds `span`. When paused or with no audio, a non-animating branch draws a static scrubber (no continuous CPU spend). This view has a **single fit-to-width time scale** (no zoom/viewport — the pinch-zoom lives only in the Epic-8 `BeatGridView`); "within bounds" is the `currentTime`-vs-`span` clamp, not a zoom claim.

**AC3 — FR-44 labeled four-field readout.**
**Given** the timeline view is visible,
**When** the user reads the text panel beneath the Canvas,
**Then** four labeled fields render (FR-44 — no bare numerics): `Estimated tempo: <X> BPM` (from `beatGrid.estimatedTempo`, `%.2f`; the `0.0` sentinel renders `Estimated tempo: unavailable`, DD8), `Beat count: <N>` (`beatGrid.beats.count`), `Downbeat status: <detected | not-detected | not-attempted>` (the real tri-state, DD2), and `Grid confidence: <0.00–1.00>` (`beatGrid.confidence`, `%.2f`, literal `Grid confidence:` label preceding the value).

**AC4 — downbeats absent.**
**Given** the analysis produced a `BeatGrid` whose `downbeats == .noneDetected` (detection ran — the demo sets `detectDownbeats = true` — and found none),
**When** the view renders,
**Then** the Canvas draws only beat ticks (zero taller downbeat marks — never a zero-confidence downbeat), and the readout shows `Downbeat status: not-detected` with `Grid confidence:` still populated. (`.notAttempted` — only reachable if a future run disables detection — renders `Downbeat status: not-attempted`, preserving the FR-28 tri-state distinction, DD2.)

**AC5 — RETIRED (superseded 2026-07-11, `cac4fe6`/PR #94).** The original constraint was "no waveform primitives in `BeatGridTimelineView.swift`." That file was DELETED and its content merged into the Epic-8 `BeatGridView` — which is a waveform view by design (its waveform pre-existed 10.3 since `eca19a3`). No **new** waveform engine (sampling/decoding) was added, so FR-39's engine non-goal still holds; the "no waveform at all" presentation letter is superseded. There is no separate file to grep.

**AC6 — INVERTED (superseded 2026-07-11, `cac4fe6`/PR #94).** The original AC mandated a Timeline/Waveform view-mode `Picker` keeping BOTH views. The operator rework instead **unified** the two into ONE merged `BeatGridView`: the Picker, `BeatGridViewMode`, `fallbackViewMode`, and the `preferredBeatGridViewMode` hydrate/persist were DELETED. The `preferredBeatGridViewMode` UserDefaults key is left **orphaned** (nothing reads/writes it; BC not a goal — recorded, no code action). `TraceView`'s `BeatGridView` usage is unchanged.

**AC6b — click-to-scrub with beat-snapping (added 2026-07-11, `cac4fe6`/PR #94).**
**Given** the merged `BeatGridView` is visible,
**When** the user clicks the lane,
**Then** the click maps content-x → time via `pointsPerSecond` and **snaps to the nearest raw detected beat** (`clickSeekTime`; exact-midpoint tie → earlier beat; finite/non-negative `>= 0` result — Copilot PR #94 fix); a click while stopped/paused starts playback; the transport is a **bordered** play/pause with a labeled disabled reason and verbatim `playbackError` render; the pure `clickSeekTime`/`scrubberX` + label statics are unit-locked in `BeatGridLogicTests` / `PlaybackControllerTests`.

**AC7 — real playback transport, result-paired and lifecycle-safe (operator decision).**
**Given** a file was analyzed and a grid published,
**When** the timeline view is shown,
**Then** playback is driven by `PlaybackController` under these contracts:
- **Result-paired load (DD5/#3/#4):** the controller loads the audio keyed to the **atomic grid publication** — `GridVisualizationState.sourceURL` (added to the payload, set in the same MainActor write as `beatGrid`) — NOT the prologue `selectedFileURL`. When `gridVisualization` becomes `nil` (every clear/failure/no-BPM path), the controller `load(nil)`s and stops. This pairs audio to the *matching* result so new audio never scrubs against the previous file's ticks.
- **Long-lived scope (DD5/#1):** `PlaybackController` **starts security scope on load and holds it for the whole player lifetime**, releasing it on replace / `load(nil)` / `deinit`. It does NOT wrap only the synchronous `AVAudioPlayer(contentsOf:)` call (the player reads lazily during `play`/`seek`, after which a short-lived scope would already be released — the shipped bug this AC exists to prevent).
- **Transport:** a play/pause control bound to the controller plays/pauses real audio; `isPlaying` reflects the actual `AVAudioPlayer` state (from `player.play()`'s Bool return + delegate). Nothing plays unprompted.
- **No-audio semantics (#12):** when audio fails to load but a grid exists, the play control is **disabled with a labeled reason**, the scrubber sits at `0`, and `seek` is a no-op. A load failure sets an observable, labeled `playbackError` (FR-44-safe); a subsequent successful load clears it.
- **Atomic replacement + end-of-track (#8/#9/#13):** a file change is one MainActor transition (stop old, detach delegate, release old scope, clear state, acquire new scope, construct/prepare, publish). The `AVAudioPlayerDelegate` end-of-track callback hops to the main actor and mutates state only when `player === currentPlayer`, setting `isPlaying = false` (stopped at 0).

**AC8 — library byte-identity + bounded demo diff.** `git diff Sources/ Tests/` is empty. The demo diff is limited to: NEW `PlaybackController.swift`, NEW `BeatGridTimelineView.swift`, NEW `BeatGridTimelineViewTests.swift` (+ any NEW test fixture), MOD `BeatGridView.swift` (add `GridVisualizationState.sourceURL` only), MOD `ContentView.swift`, MOD `AnalysisViewModel.swift`, and the pbxproj/xctestplan membership for the new files — no other files change.

## Dev Notes

### What this story is (and is NOT)
It is (a) a NEW waveform-free `BeatGridTimelineView` (the FR-39 consumer-facing beat/downbeat timeline + labeled readout), (b) a NEW `PlaybackController` giving the demo its first real audio playback so the scrubber has a live clock, and (c) a view-mode switch so the user can flip to the existing Epic-8 `BeatGridView`. It is NOT a change to the library, NOT a deletion of the Epic-8 view, NOT waveform rendering in the new file, and NOT a change to the analysis pipeline (the only `AnalysisViewModel` production change is adding `sourceURL` to the atomic grid payload + the view-mode preference).

### Recorded design decisions (flag at PR, mirroring the 9.x / 10.1 / 10.2 precedent)
- **DD1 — grid lives on `CombinedAnalysisResult.beatGrid`, not `AudioAnalysisResult`.** The epic AC says "an `AudioAnalysisResult` carrying a non-nil `BeatGrid`" — factually wrong (same class as 10.2's `allEntries()`). `AudioAnalysisResult` has no `beatGrid`; `CombinedAnalysisResult` (returned by `analyze(url:options:)`) does. The demo already threads `combined.beatGrid` into `GridVisualizationState.beatGrid`; the new view consumes that payload.
- **DD2 — `DownbeatResult` has no "partial" state.** The epic AC lists `<detected | not-detected | partial>`; the real tri-state is `.notAttempted / .noneDetected / .detected(estimate:)`. Readout maps `.detected → "detected"`, `.noneDetected → "not-detected"`, `.notAttempted → "not-attempted"` — preserving the FR-28 distinction ("never ran" vs "ran, found none"). Because the demo runs `detectDownbeats = true`, AC4's no-downbeat case is `.noneDetected → "not-detected"`, matching the epic's literal text.
- **DD3 — a full Epic-8 `BeatGridView` already exists; it is kept.** `Demo/.../BeatGridView.swift` (from `eca19a3` "Land epic 8") already Canvas-draws waveform + raw beats + extrapolated grid + downbeats + anchor, with a labeled `BeatGridDetailSection` readout and a legend popover, wired into `ContentView.beatGridSection` and `TraceView`. Per the operator decision, 10.3 adds the new view alongside it behind a switch (AC6) — it does not replace or delete it. `BeatGridView`/`BeatGridDetailSection`/`BeatGridHelpButton` and their `TraceView` use stay as-is (the only edit to that file is the additive `GridVisualizationState.sourceURL` field).
- **DD4 — beat ticks are raw `beats`; downbeat markers are the estimate's `beats`.** AC1 is literal: "a vertical tick mark for each `BeatTimestamp`." The new view draws one tick per `beatGrid.beats` element (raw detected beats) + taller marks at every `DownbeatEstimate.beats` timestamp of a `.detected` result (the payload's beat times ARE the downbeats — do NOT derive from `phaseIndex`/meter) + the anchor. This is intentionally different from the old `BeatGridView`, which showcases the drift-free *extrapolated* grid for sync; the new FR-39 timeline is the plain beats-and-downbeats readout. (The `BeatGrid` DocC "extrapolate, don't trust raw beats" caveat is about sync math, not this inspection tick layer.)
- **DD5 — playback is a NEW substrate with a LONG-LIVED security scope (operator decision; Codex- + party-hardened).** AC2 says "the audio is mid-playback"; the demo had no transport. `PlaybackController` (`@MainActor @Observable`, `NSObject`, wrapping the injectable `AudioPlaybackEngine`) is owned by `ContentView` as `@State`. **`PlaybackController()` does NO I/O in `init`** (unlike `ModelCatalog()`, whose expensive `restore()` forced the 10.2 R3 App-hoist) — the file loads only when `.onChange` fires — so a `ContentView` `@State` default-init does not regress the R3 lesson (F7). **The scope must span the player's lifetime, NOT just `AVAudioPlayer(contentsOf:)`.** `AVAudioPlayer` reads audio lazily during `play()`/`seek()`; a synchronous `withSecurityScopedAccess { AVAudioPlayer(contentsOf:) }` would `stopAccessingSecurityScopedResource()` before playback ever reads — working for a drag/dropped file (transient scope still active) while silently failing for a restored-bookmark file. So the controller calls `startAccessingSecurityScopedResource()` on `load`, retains the scoped URL, and releases it on replace / `load(nil)` (`load` is an atomic MainActor replacement — stop, detach delegate, **release old scope before acquiring the new one** so a same-URL re-entry cannot leak a refcounted grant, F6 — clear, acquire new scope, construct/prepare, publish). **Deterministic release is `load(nil)` + `ContentView.onDisappear`, NOT `deinit` (F3):** a `@MainActor` class's `deinit` is `nonisolated` under Swift 6 and cannot touch main-actor state or `await` a hop, so `deinit` is only a best-effort backstop over the `Sendable` scoped URL (release the retained scoped URL; do not read other main-actor stored state). `AVAudioPlayer` is non-`Sendable` → MainActor-confined; the completion callback hops to `@MainActor` and applies only if its **generation token equals the current one** — a monotonic `Int` bumped on every `load`, carried by the callback — NOT pointer `===` (the controller holds an `AudioPlaybackEngine` protocol, not the concrete player, so pointer identity can't reach through the seam, F5). The scoped URL is `GridVisualizationState.sourceURL` (a resolved bookmark URL from a restored session arrives scope-unstarted — the `start` is what grants read access).
- **DD6 — one time→x map; `span` tracks the ANALYZED coverage; scrubber clamped, ticks omitted.** Both ticks and scrubber map `x = time / span · width`; the scrubber x is additionally clamped `[0, width]`, while an out-of-`[0,span]` **tick** is omitted (not piled at an edge, #16). **`span` is the analyzed span, NOT the full-file playback duration (F1):** `.fullTrack` coverage is bounded by `Options.maxSeconds` (`AudioAnalysisService.swift:344`; default 120, demo raises to ≤600), so on a file longer than the cap `beatGrid.beats` stop early while `AVAudioPlayer.duration` is the whole asset — preferring `controller.duration` would bunch every tick into the left of the Canvas. So `span` is the **first finite value `> 0`** among `state.duration` (the waveform decode span, itself `maxSeconds`-capped), the last beat time, `controller.duration` (only if `hasAudio`, as a last resort when there is no analyzed span), and `1` — never `0`/non-finite (division guard). Playback past the analyzed span pins the scrubber at the right edge (honest: the grid ended there); the clamp guarantees it never escapes the Canvas. The pure mappers defend non-finite `time`/`width` and non-positive `span`; empty `beats` + `nil` anchor + `width == 0` draw only the baseline frame.
- **DD11 — observable `currentTime` snapshot so a paused seek redraws (F2).** AC2's CPU-saving non-animating branch (drawn when `!isPlaying || !hasAudio`) and the live scrubber conflict: a `seek` while paused mutates the engine but, if `currentTime` is a computed passthrough, does not invalidate the view, so the scrubber lies until play. Fix: `PlaybackController` holds a **stored `@Observable currentTime: Double`** written by the animation tick AND on every `seek`/`load`, so the paused branch reads observable state and redraws once on a paused seek. The `TimelineView(.animation)` branch still drives the moving scrubber while playing.
- **DD7 — view-mode persists via the demo UserDefaults convention, with write-back.** `beatGridViewMode` (a `String`-raw enum) hydrates via `object(forKey:) == nil` genuine-absence detection (NOT `string(forKey:)`), persists the stable `rawValue`, and self-heals a present-but-unusable value by **removing the key and writing back `.timeline`** (not merely returning `.timeline` in memory, #17) — mirroring `AnalysisViewModel`'s merge-strategy/ensemble-preset hydrate. Default `.timeline`. Housing it on `AnalysisViewModel` (with its injected `UserDefaults`) makes it suite-isolated-testable like the siblings.
- **DD8 — FR-44 readout, sentinel-safe.** All four fields are `Text("<label>: …")` / `LabeledContent` forms that begin with a letter, so `confidence-label-audit.sh` (which flags only bare `\(…confidence/score/…)` interpolations) passes. `Grid confidence:` is `%.2f` in `[0,1]` (two decimals per AC3). `Estimated tempo:` guards the documented `estimatedTempo == 0.0` "no valid estimate" sentinel → `Estimated tempo: unavailable` (mirrors 10.4's `True peak: unavailable` labeled-fallback discipline).
- **DD9 — `BeatGridTimelineView.swift` carries zero waveform primitives (AC5 grep).** No `Waveform.decode`, `peaks`, `AVAudioFile`, FFT, or per-sample loop in that file. The `AVAudioPlayer` is playback and lives in the separate `PlaybackController.swift`, so the AC5 grep against `BeatGridTimelineView.swift` is clean by construction. The new view ignores `state.peaks` entirely.
- **DD10 — testability via a player-seam, not a read-only clock.** The pure geometry + label derivations are `nonisolated` and CI-tested deterministically. `PlaybackController` depends on an injectable `AudioPlaybackEngine` protocol + `makeEngine` factory (production = `AVAudioPlayer`-backed; a fake in tests) so `isPlaying`/`seek`/`load`-failure/delegate-identity transitions are CI-testable **with observable state tied to the (fake) engine** — a read-only "now" closure could not validate `isPlaying`. A bundled fixture proves in-process load/prepare/seek against the real AVAudioPlayer engine; the cross-launch restored-bookmark sandbox-authorization path is operator-only (AC7/#2).

### Playback-scope discipline (inherited from 10.1/10.2, extended in DD5)
The audio file is user-selected (drag/drop or open panel) or a restored bookmark. Unlike the 10.2 register/load path (a single synchronous read inside `withSecurityScopedAccess`), **playback needs the scope held across the whole player lifetime** because `AVAudioPlayer` reads lazily. `PlaybackController` owns that lifetime (start on `load`, release on replace/`load(nil)`/`deinit`) rather than using the synchronous static bracket.

### Testability honesty
See DD10. CI covers geometry + labels + `PlaybackController` state transitions (via the fake engine) + the view-mode write-back; a bundled fixture covers real in-process AVAudioPlayer load/seek; GUI/operator covers the live Canvas render and the cross-launch restored-bookmark authorization. No vacuous tests — each pure helper and each controller transition has an input→expected assertion, mirroring the 10.2 `ModelCatalogTests` discipline.

### Layout (beatGridSection)
The `maxHeight: 340` cap on `beatGridSection` is load-bearing (an unbounded beat-grid block starves the BPM hero). Adding a `Picker` + transport + readout must not clip: give the Canvas a defined **minimum height**, put the readout/transport in the fixed region and let the Canvas flex within the cap, and verify legibility under larger Dynamic Type. If the cap and the added controls genuinely cannot coexist demo-locally, that is a HALT trigger (below).

### Boundaries (autonomous-run guardrails — HALT if any trigger)
