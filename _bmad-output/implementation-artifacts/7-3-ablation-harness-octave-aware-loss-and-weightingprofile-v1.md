## Story

**As a** library maintainer,
**I want** the KDD-B2 head-to-head ablation harness wired with both training paths — (a) supervised-with-augmentation [tempo-class-preserving time-stretch + octave-aware pitch-shift + noise injection] and (b) masked-mel pretraining → fine-tune — running against the v1 feature pipeline as scaffolding, with an octave-aware training loss (FR-16) and a single declared `WeightingProfile` per training run (Guardrail 3),
**So that** the ablation comparison axes (Acc1 + inference latency + memory footprint + ECE / reliability diagram / softmax entropy + leave-artist-out delta vs random-split delta) are measurable end-to-end on v1 before Story 7.5 swaps in the substrate-locked v2 features — with **disposable** model weights/metrics (Guardrail 1) but reusable harness, loss, and comparison plumbing.

**AC2 — Octave-aware loss, FR-16 (epic AC2, L677-679).**
**Given** the octave-aware loss in a shared `ablation/octave_aware_loss.py` consumed by both training scripts,
**When** the loss is reviewed,
**Then** it penalizes octave-equivalent predictions (target bin `T`; predictions at `T`, `2T`, `T/2`) with a documented per-class weighting **that does not collapse the octave penalty to 0** — i.e. predicting `2T`/`T/2` still incurs strictly-positive loss, smaller than a far-off prediction but never free. ### Design Decisions

**DD #1 — New Tony-split loader (net-new join, NOT a `load_tony_corpus` reuse); do NOT reuse `build_splits()` (legacy GiantSteps).** `train.py` trains on GiantSteps; the ablation must train on the Story-7.1 Tony split. **The join is net-new logic**, not a single function call: `corpus_common.load_tony_corpus()` returns ALL 1,344 tracks + provenance — it does NOT read `corpus_splits.json` or filter to the split. The loader must: load all tracks → index by `track_id` → select per the split's id-lists. **Shapes (verified, do not guess):** `corpus_splits.json` `tony.train` (820) and `tony.val` (92) are flat string lists; `tony.leaveArtistOut` is a **dict** — the 104 ids are at `tony.leaveArtistOut.heldOutTrackIds` (`heldOutCount: 104`), and run-B artist grouping is at `.trainArtists`/`.heldOutArtists`. The join is **string-keyed** (both `corpus_splits.json` ids and `tony-truth-labels.json` `track_id` are strings — NO `int()` cast). Per record use only `local_path` (byte locator) + `bpm_truth` (label). Reconcile loaded counts (820/92/104) vs the JSON, loud-fail on drift (`corpus_common` discipline). Leave `build_splits()` untouched — it still serves `externalEval` + the GiantSteps pipeline. **Never** read `signals.*`/`artist`/`album`/`playlist` (FR-15 forbidden, `label-tier-policy-v1.md` §FR-15).

**DD #2 — Octave-aware loss is net-new (FR-16); soft-target CE with valid-octave-only partial credit (Codex/Winston 2026-06-02).** Replace one-hot CE with a soft target placing primary mass on bin `T` and documented partial-credit mass on the octave family `{2T, T/2}`. "Does not collapse to 0" (AC2) = predicting an octave still costs loss (less than a far-off bin, never free) — teaches octave structure WITHOUT licensing octave errors. **Construction (precise, to avoid the clamp defect):** (1) compute octave-partner BPMs in BPM space (`2·bpm`, `bpm/2`); (2) **DROP any partner whose BPM falls outside `[30, 285]`** and redistribute its mass to bin `T` — do NOT let `bpm_to_bin`'s clamp smear octave credit onto a boundary bin (real defect: DnB ~170 → `2T=340` would clamp to bin 255/285 BPM; ~32 → `T/2=16` clamps to bin 0); (3) map surviving partners to bins, **merge duplicate bins** before assigning mass; (4) apply label-smoothing **once** (not double-counted with the partial-credit mass), and **renormalize the target vector to sum to 1.0**. The loader yields the integer bin (`bpm - 30`), so the soft target maps `bin → bpm → {2·bpm, bpm/2} → bin` — never `2·bin`. Bin mapping = a 3-line clamp helper **replicated locally in `octave_aware_loss.py`** (do not import `dataset.bpm_to_bin` — it does not exist; the real `bpm_to_bin` is `reference_arch.py:47`, reachable via the `model.py` sys.path pattern, but a local copy keeps the develop-only loss module self-contained). Pure torch (`-(soft_target * log_softmax(logits)).sum(1).mean()`). The partial-credit constant is **held identical across both arms** (DD #12). Document the formula + constants + Schreiber & Müller 2018 (tempo-octave error taxonomy) + Hendrycks & Gimpel 2017 (calibration tie-in) in `octave-aware-loss.md`. **Octave-risk tie to 7.2 (DD #6 there):** `secondarySupervised` `bpm_truth` may enshrine a DSP octave error; this loss is the trainer-side backstop.

**DD #3 — Commit an FR-15-clean unsupervised-pretrain manifest.** The masked-mel arm needs the `unsupervisedPool`, which is only in the gitignored survey JSON. `build_unsupervised_manifest.py` reads the (regenerable) survey, emits `non-rekordbox-unsupervised-pretrain-manifest.json` with `{audioHash, relPath}` ONLY (no labels — masked-mel is self-supervised; no forbidden signals), `file_sha256` derivation pinned in the header. Mirrors the 7.2 secondary-manifest pattern (git-durable, reproducible). Loud-fail with the `make non-rekordbox-survey` hint if the survey is absent.

**DD #4 — FR-15 grep scoped to the feature transform; locator segregated (7.2-AC9 precedent).** The literal `rg -i "...path..." ablation/*.py` is unsatisfiable (the loader needs `relPath` to fetch bytes). Resolution: the **feature transform** (PCM `np.ndarray` + `bpm` → model-input tensor) lives in module(s) that import the FR-15-clean `dataset` helpers and reference **no** path/playlist/rekordbox/artist/id3 token; the **file LOCATOR** (manifest/labels read + `relPath`/`local_path` → librosa decode) is a separate, audited module out of feature-grep scope (a locator is not a model feature — the exact distinction 7.2 AC9 drew for `relPath`). The AC7 grep targets the feature-transform module(s) and returns zero; `fr15-audio-only-audit.md` records the boundary + grep result.

**DD #5 — Net-new label-preserving octave-aware pitch-shift augmentation, applied identically in BOTH arms' fine-tune; reliability diagram is JSON+MD at v1.** Current `dataset.augment_pcm` does resample tempo-stretch (label-rebinding, co-shifts pitch) + gain + pink noise — no INDEPENDENT pitch-shift. Epic AC-a lists "octave-aware pitch-shift" as a distinct augmentation: add a **label-preserving** pitch-shift (`librosa.effects.pitch_shift`, ±N semitones, BPM unchanged — pitch-shift does not alter tempo, so it is octave-/tempo-class-preserving by construction; "octave-aware" = bounded so it stays musically sensible). The full augmentation set (tempo-stretch + pitch-shift + gain + noise) is applied **identically in BOTH arms' supervised fine-tune** — augmentation is a held-fixed confound, NOT the variable that distinguishes the arms (the variable is encoder init; DD #12). The arm name "supervisedAugmented" reflects the epic's naming, not an augmentation asymmetry. **Terminology (Codex 2026-06-02):** the epic's "tempo-class-preserving time-stretch" is imprecise — the existing `augment_pcm` ±4% resample DOES change tempo and RE-BINDS the BPM label; it is a **label-preserving small tempo perturbation** (bounded so the relabel stays within the `acc_4pct` tolerance), NOT true tempo invariance. The pitch-shift is the truly tempo-preserving one (BPM unchanged). Reliability diagram: matplotlib is not a dep → emit bin-confidence/accuracy JSON + a Markdown table at v1; Story 7.7 produces the `.png` (FR-25).

**DD #13 — Masked-mel pretraining recipe (pinned; Codex/Winston/Amelia 2026-06-02 — the #1 cross-reviewer gap).** The masked-mel arm underwrites half the headline comparison, so the SSL recipe must be concrete, not invented ad-hoc. **Encoder split:** the transferable encoder is `TempoCNN.block1 → pool1(1,5) → block2 → pool2(1,4) → block3`, producing latent `(N, 96, 128, T/20)` — i.e. everything BEFORE the GAP (`AdaptiveAvgPool2d((1,1))`); the conv stack downsamples time 20× (5×4) and never touches the mel axis. **Masking:** input-space, contiguous **time-frame spans** on the z-scored log-mel (NOT mel-band masking — that would change frequency weighting semantics), ~**15%** of frames, span length ~5 frames, mask value = 0 (post-z-score per-band mean), deterministic from the run seed. **Decoder:** a lightweight reconstruction head (transpose-conv or `interpolate`-and-1×1-projection) that undoes the 20× time pooling back to `(N, 1, 128, T)` — DISCARDED after pretraining (only `block1/2/3` weights transfer). **Loss:** MSE on the **masked positions only** (not full-frame reconstruction). **Transfer:** initialize the fine-tune model's `block1/2/3` from the pretrained encoder, then fine-tune ALL layers (do NOT freeze — freezing would be a different comparison). **Budgets:** the fine-tune budget equals the supervised arm's (`--epochs`, shared per DD #12); the **pretrain budget is a separate flag** (`--pretrain-epochs`, default e.g. 30) recorded in `model_metadata.json` (NOT counted against the shared fine-tune budget).
