# Story 8.12: Manual anchor reposition (snap-toggleable)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a **DJ-app user hand-correcting a beat grid** (the Rekordbox-style consumer, 2manyDJs),
I want **to set the grid's bar-origin anchor by hand — snapping to the nearest detected beat by default, OR placing it at an exact time with snapping turned off — complementing the already-shipping manual BPM lock**,
so that **I can lock the grid Rekordbox-style (click a new downbeat, optionally fine-place it off-beat, adjust BPM) when auto-detection placed the bar phase wrong or was off entirely.**

## Context & why this story exists

This is **pillar 3 of 3** in the beat-grid accuracy follow-up (operator decision 2026-06-23, `epics.md:1208`): **8-10** continuous tempo refinement (`done`), **8-11** drop-anchored downbeat / measure-top (`done`, PR #54 / commit `a286475`), **8-12** = this story. The manual *BPM*-lock half already ships — `BeatGridTempoLock.bpm(Double)` (Story 8.9, `BeatGridTempoLock.swift:62`). The missing complementary primitive is a manual *anchor* (bar-origin) override: when the auto downbeat / phase-consistency anchor lands on the wrong beat — or auto-detection abstained entirely (the common case: 8.5a `.metricalAccent` fires ~4.4 %; 8.11 `.structuralDrop` is also abstain-heavy by design) — the human asserts the bar origin. Together the two are the hand-correction levers of a Rekordbox-style grid editor: **set the BPM** (shipped) + **set the downbeat** (this story).

**Operator directive (2026-06-28): the snap must be toggleable.** The first draft of this story scoped snap-to-nearest-detected-beat *only*. The operator clarified — twice — that being able to **turn the snap off and reposition to an arbitrary time** is a required feature ("being able to turn off the snap-to is a useful feature"; "I do want to be able to snap to the beat, but also turn it off for repositioning"). That is the truer Rekordbox model: Rekordbox's own grid-marker edit places the bar line at the waveform/playhead position, not constrained to an internal detected-beat list (Codex consult thread `019f1079`). Honoring it is **not** a mode flag bolted onto a type that cannot express an off-beat anchor — it requires a deliberate, honest **anchor-model evolution** so a free-standing manual origin is a first-class representable state (Codex consult thread `019f1095`). That evolution is the bulk of this story; the transform itself is small.

**Why the model must change.** `BeatGrid.gridOrigin` carries a load-bearing invariant (`BeatGrid.swift:239-248`): a non-nil anchor's `beatIndex` must index a real entry of `beats`, AND the anchor's `presentationTime` is **rebuilt from `beats[beatIndex]`** at every init/decode path (any caller time is overwritten). So today the anchor literally cannot carry a time that does not coincide with a detected beat. To represent an off-beat manual origin honestly, `beatIndex` becomes **optional provenance** (`Int?`): present ⇒ "this anchor is coupled to that detected beat" (keep the rebuild); `nil` ⇒ "free-standing manual time, authoritative on its own." This is a pre-1.0 type change with no BC promised (`feedback_no_bc_goal_prerelease`).

## Key Design Decisions (DD)

1. **Snap is toggleable via an enum mode; default `.snapToNearestBeat` (operator directive).** Add `public enum BeatGridAnchorRepositionMode: Sendable, Equatable, CaseIterable { case snapToNearestBeat; case exactTime }` — a transient call-time parameter, **NOT `Codable`/`Hashable`** (it is never persisted in `BeatGrid`; this mirrors the sibling parameter-enum `BeatGridTempoLock` (`BeatGridTempoLock.swift:47`), which is `Sendable, Equatable` only — `Codable` belongs on the persisted `BeatGridAnchorSource`, not on a call argument; `CaseIterable` is kept only for the `allCases.count == 2` exhaustiveness lock + documented room for `.nearestDownbeat`/`.nearestBar`) — and `public func repositioningAnchor(to time: Double, mode: BeatGridAnchorRepositionMode = .snapToNearestBeat) -> BeatGrid`. `.snapToNearestBeat` maps the caller's time to the nearest detected beat (anchor *coupled*: `beatIndex` set, time taken from that beat). `.exactTime` places a free-standing anchor at the caller's clamped time (anchor *decoupled*: `beatIndex == nil`). An **enum, not a `Bool`** (Codex `019f1095`): cleaner public surface and leaves room for later `.nearestDownbeat` / `.nearestBar` without a second boolean. The default preserves the most-useful, least-surprising behavior (snap on); both modes set `source == .manual` (provenance = a human placed it). A `Bool` flag that pretended the *old* type could express an off-beat anchor was the rejected design (Codex `019f1079`: "advertises a capability the type cannot honestly support") — the enum is honest *because* the model now backs both states.

2. **`BeatGridAnchor.beatIndex: Int` → `Int?` (optional provenance), the honest representation (Codex `019f1095`, chosen over source-discrimination).** `beatIndex` now describes the **mechanical coupling**, not the provenance: `!= nil` ⇒ coupled to `beats[beatIndex]` (rebuild applies); `== nil` ⇒ free-standing, `presentationTime` authoritative. `source` stays pure provenance (`medianConsistentBeat`/`strongestBeat`/`firstBeat`/`downbeat`/**new** `.manual`) and does **not** by itself decide coupling — so a *snapped* manual anchor is `beatIndex: someIndex, source: .manual` and an *unsnapped* manual anchor is `beatIndex: nil, source: .manual`. Chosen over a `source`-discriminated rule ("only `.manual` may decouple") because the optional index *is* the discriminator and is less error-prone than threading `source` checks through every coupling site. `Int?` stays `Hashable`/`Equatable`-clean (no `Double`, no NaN). The memberwise init keeps `max(0, …)` clamping for a *present* negative index (`BeatGridAnchor.swift:80`); a `nil` index passes through.

3. **`BeatGrid.init` cross-field invariant — three rules, both the memberwise and `Codable` paths (Codex `019f1095` §2).** Replace the single in-range-rebuild (`BeatGrid.swift:239-248`) with:
   - **(a) `beatIndex` present AND in range** (`0..<beats.count`) → keep the anchor; **rebuild** `presentationTime`/`confidence`/`strength` from `beats[beatIndex]`; preserve `beatIndex` + `source` (verbatim today's behavior — the auto-anchor path is unchanged).
   - **(b) `beatIndex` present AND out of range** → **drop the whole anchor to `nil`** (NOT promote it to a free-standing anchor at its stale time — an anchor that *claimed* a beat relationship which is invalid is hostile/stale; discard it). This holds **even when `source == .manual`** — the dropped `presentationTime` is a stale copy of a now-absent coupled beat, NOT an asserted free placement (a genuinely free origin always carries `beatIndex == nil` and survives via rule (c)), so no recoverable user intent is lost (the only producers of present-out-of-range are hostile decode or beats-trimming, which is out of scope).
   - **(c) `beatIndex == nil`** → keep the anchor **iff `source == .manual`**, with `presentationTime`/`confidence`/`strength` clamped as supplied (the free-standing manual case); a `nil`-index **non-`.manual`** anchor is **incoherent** (an auto source must name its beat) and is **dropped to `nil`** (sanitization). This is the safe hostile-decode posture: a decoded payload cannot smuggle a free-standing non-manual origin.
   `BeatGridAnchor.init` stays permissive (it cannot see `beats` or judge coherence); `BeatGrid.init` remains the sole cross-field gate (the existing doctrine, `BeatGrid.swift:228-238`).

4. **`offset(by:)` must shift a free-standing anchor directly (Codex `019f1095` §3).** Today `offset(by:)` (`BeatGrid.swift:387-437`) passes the original `gridOrigin` back through init and relies on the rebuild to move a coupled anchor with its shifted `beats[beatIndex]`. A `nil`-index manual anchor has **no beat to follow**, and init rule (c) does **not** rebuild it (it keeps `presentationTime` as supplied) — so without explicit handling it would round-trip at its *original* time. **Three concrete changes (the third is load-bearing):** (i) compute `minTime`/`maxTime` over the **union of all movable timestamps** — `beats`, detected-downbeat `estimate.beats`, AND a free-standing (`nil`-index) `gridOrigin.presentationTime` — taking `min`/`max` over that whole sequence rather than folding the anchor into the current `?? 0`-seeded value (`:392-399`); else an empty-`beats` grid seeds `minTime = 0` and a lone free anchor at e.g. 100 s can never move earlier (a `−50` would clamp to `0` and no-op); (ii) replace the `!beats.isEmpty` no-op guard (`:388`) with "no-op only when there are **no movable timestamps** (no `beats`, no detected-downbeat beats, no free anchor)" so a `beats: []` + free-standing-manual grid (a legal state — DD #6) still offsets; (iii) **branch on anchor kind when reconstructing** — **only when `gridOrigin.beatIndex == nil`**, build a shifted free-standing anchor (`presentationTime + effective`, `beatIndex == nil`, `source`/`confidence`/`strength` forwarded) and pass THAT in place of `gridOrigin: gridOrigin` (`:434`); when the anchor is **coupled** (`beatIndex != nil`) or `gridOrigin == nil`, pass the **original** `gridOrigin` unchanged so init rebuilds it from the shifted `beats[beatIndex]` exactly as today (do NOT replace a coupled anchor with a `nil`-index one — that would strip its coupling). The `shifted(_:)` helper (`:409-413`) maps `BeatTimestamp` only; the `:426-427` "init rebuilds from the SHIFTED `beats[beatIndex]`" comment is true ONLY for the coupled branch — amend it to note the `nil`-index branch shifts the anchor's own time directly (init rule (c) won't rebuild it).

5. **Bump `BeatGrid.currentSchemaVersion` 1 → 2 (Codex `019f1095` §5) — and re-capture the Story-8.11 committed snapshot.** The persisted `BeatGridAnchor` contract changes (`beatIndex` becomes optional; a `nil` index now carries the "free-standing manual" meaning; a free-standing manual grid omits the `beatIndex` key, which a v1 decoder's `decode(Int.self)` would *throw* on). Bump `currentSchemaVersion` (`BeatGrid.swift:78`) to stamp the evolved contract. **Consequence (must handle):** the Story-8.11 always-run snapshot `DownbeatStrategyContainmentTests.defaultPathBeatGridMatchesPreStorySnapshot` (`:176-197`) hashes `JSONEncoder().encode(grid)`, which **includes `schemaVersion`** — so the default-path grid's JSON changes (`schemaVersion: 2`) and the committed SHA-256 (`5019b4fa0dccb5dfd8a52ce98eef2b16bac62b80bde02109f61bb0a09a239c9b`) **must be re-captured**. The default-path grid is otherwise byte-identical (the auto anchor keeps a non-nil `beatIndex`, same beats/tempo/confidence); only the version stamp moves. Re-capture it, and note in the test comment that the delta is the deliberate 8-12 schema bump (not a behavioral regression). **Beyond the one SHA digest, the dedicated `schemaVersion == 1` unit assertions in `BeatGridTypesTests` also flip to `2`** — `:1005` `currentSchemaVersion`, `:1006` `noRunSentinel`, `:1010` fresh-grid stamp, `:1028` emitted value — but **NOT** `:1021` (absent→1 decode) or `:1039` (unknown-future), which stay valid (see Task 5). *(Decision point flagged for the operator: bump-and-recapture (recommended, honest contract stamp) vs. don't-bump — since a free-standing-manual grid already shape-throws in a v1 decoder, the version field is arguably redundant for that case; bumping is the conservative, consumer-honest choice and the re-capture cost is one hash.)*

6. **New `BeatGridAnchorSource.manual` (provenance); human-asserted = bar-trustworthy, coupling-orthogonal.** Add `case manual` (raw `"manual"`) to `BeatGridAnchorSource` (`BeatGridAnchor.swift:124-141`; `String`-backed → bare-string wire shape; closed set; **not** `CaseIterable`, matching the four existing cases). `.manual` records that a human placed the origin and is **independent of `beatIndex` coupling** (a `.manual` anchor may be snapped *or* free-standing — DD #2). It is a **distinct, independently bar-trustworthy** provenance: the transform leaves `downbeats` untouched (it does not synthesize a `DownbeatResult`), so a `.manual` origin can coexist with `downbeats == .notAttempted` — and the `BeatGrid.init` `source`-gate DocC (`BeatGrid.swift:204-207`, `:236-238`) is updated so a bar-snap consumer knows `source == .manual` is a deliberate user override of the bar origin, distinct from the auto `.downbeat` dual-gate (`source == .downbeat` AND `downbeats == .detected`). **The DocC must make the decoded-trust asymmetry the explicit point, not a footnote:** the existing rule says "on a decoded payload `source` is untrusted — gate on `.downbeat` AND `downbeats == .detected`, never `source` alone"; `.manual` is the one provenance with **no second field to corroborate** (it coexists with `.notAttempted`), so "honor `source == .manual`" IS trusting `source` alone — and that is acceptable *only because* a `.manual` origin is inherited from whoever wrote the payload (typically the consumer's **own cache**), unlike `.downbeat` which is cross-checked against detection. State that asymmetry; it is the reason rule (c) deliberately admits a decoded free-standing `.manual` origin (bounded only by finite/non-negative clamping — no duration check, see Out of scope).

7. **Repositions the anchor ONLY; pure-value, deterministic, total; no analysis-path / corpus impact (auto-anchor values unchanged + schema stamp).** The transform forwards every non-`gridOrigin` field (W52 forward-every-field, `BeatGrid.swift:262-296` precedent): `beats`, `downbeats`, `estimatedTempo`, `confidence`, `tempoAgreement`, `coverage` unchanged; `schemaVersion` carries the bump only on freshly-produced grids (the transform itself forwards `self.schemaVersion`). Total-function no-ops: a **non-finite** `time` → `self`; `.snapToNearestBeat` on an **empty-`beats`** grid → `self` (nothing to snap to); `.exactTime` works even on empty `beats` (a free-standing origin needs none). Nearest beat = `argmin |beat.presentationTime − time|`, ties → **lower `beatIndex`** (earlier beat), test-locked. **The auto pipeline's anchor VALUES are unchanged** (reserve "byte-identical" for the transform's self-vs-result field comparison in AC #9 — an auto grid's *serialized bytes* do move, by exactly the `schemaVersion` stamp): `selectGridOrigin` (`BeatGridAnalyzer.swift:574-641`) and the `.detected → .downbeat` repoint (`:411-418`) pass a literal `Int` that widens to `Int?` with a non-nil value, so every auto-produced grid's *values* are unchanged; the `schemaVersion` stamp 1→2 (DD #5) is the **one intended byte delta** (one re-captured SHA + the four `== 1` assertions). The transform is never invoked in `analyzeBPM`/`analyzeBeatGrid`/`analyze`, never feeds BPM selection → OA300 (Acc1 ≥ 57/82, Acc2 ≥ 73/82) / GiantSteps (Acc1 ≥ 537/661, Acc2 ≥ 546/661) hold by construction. There is **no `Options`-gated default-on path**, so the only "byte-identity opt-out" obligation is the auto-anchor-unchanged + schema-bump locks above — state this explicitly in Completion Notes.

## Acceptance Criteria

1. **Configurable transform.** `public func repositioningAnchor(to time: Double, mode: BeatGridAnchorRepositionMode = .snapToNearestBeat) -> BeatGrid` is added to `BeatGrid` (pure value, non-mutating, no re-decode), with `public enum BeatGridAnchorRepositionMode: Sendable, Equatable, CaseIterable { case snapToNearestBeat; case exactTime }` (transient parameter — **not** `Codable`/`Hashable`, matching the `BeatGridTempoLock` precedent). `.snapToNearestBeat` → returned `gridOrigin` has `beatIndex` = nearest beat's index, time/confidence/strength from that beat, `source == .manual`. `.exactTime` → returned `gridOrigin` has `beatIndex == nil`, `presentationTime ==` the clamped caller time, `source == .manual`. Every other field is bit-identical to `self`. A unit test locks `BeatGridAnchorRepositionMode.allCases.count == 2` + exhaustive `switch` (DD #1, #7).

2. **`beatIndex: Int?` anchor-model evolution.** `BeatGridAnchor.beatIndex` is `Int?`. A present index keeps `max(0, …)` clamping; `nil` passes through. `BeatGridAnchor` stays `Sendable, Hashable, Codable, CustomStringConvertible`; `description` prints the optional (e.g. `beat nil`/`beat 3`). The synthesized `Codable` omits the `beatIndex` key when `nil`; a custom decode (`decodeIfPresent`) re-clamps a *present* negative index to `0` and treats missing/`null` as `nil` (DD #2).

3. **`BeatGrid.init` three-rule invariant (memberwise AND `Codable`):** (a) present + in range → rebuild from `beats[beatIndex]`, preserve index + source; (b) present + out of range → drop the whole anchor to `nil` (incl. `source == .manual`); (c) `nil` index → keep iff `source == .manual` (clamp fields), else drop to `nil`. Tests pin all three on both paths, including a decoded out-of-range `.manual` anchor (dropped) and a decoded `nil`-index `.firstBeat` anchor (dropped) (DD #3).

4. **`gridOrigin` invariant still holds for coupled anchors, relaxes for free-standing:** when `gridOrigin != nil` AND `gridOrigin.beatIndex != nil`, then `beatIndex ∈ 0..<beats.count` AND `beats[beatIndex].presentationTime == gridOrigin.presentationTime` (the existing safe-subscript contract, now guarded by `if let`). When `gridOrigin.beatIndex == nil`, the anchor is free-standing and its `presentationTime` stands alone. A `Codable` round-trip of a free-standing manual grid preserves the arbitrary `presentationTime` unchanged (DD #2, #3).

5. **`offset(by:)` shifts both anchor kinds correctly:** a coupled anchor follows its shifted `beats[beatIndex]` (unchanged); a free-standing (`nil`-index) anchor is shifted **directly** — `offset(by:)` builds the shifted anchor and passes it, since init rule (c) does not rebuild it; `minTime`/`maxTime` are taken over the **union** of movable timestamps (so a lone free anchor seeds them — NOT a `?? 0` fold); a `beats: []` + free-standing-manual grid still offsets its anchor (the `!beats.isEmpty` guard → no-movable-timestamps check). Tests pin each, **including: a `−50` offset of a lone free anchor at 100 s on an empty-`beats` grid shifts it to 50 (proving `minTime` is seeded from the anchor's own time, not the `?? 0` fold that would no-op it); a `−150` offset clamps the delta so the anchor lands at 0** (DD #4).

6. **Schema bump + committed-assertion updates:** `BeatGrid.currentSchemaVersion == 2`; a freshly-produced grid stamps `2`; the decoder still faithfully decodes a legacy `schemaVersion: 1` (and an absent version → 1) without throwing. `DownbeatStrategyContainmentTests.defaultPathBeatGridMatchesPreStorySnapshot` is re-captured to the new SHA-256 with a comment attributing the delta to the 8-12 schema bump; **and the four `BeatGridTypesTests` `schemaVersion == 1` stamp assertions flip to `2` — `:1005` (`currentSchemaVersion`), `:1006` (`noRunSentinel`), `:1010` (fresh-grid stamp), `:1028` (emitted value) — while `:1021` (absent→1 decode) and `:1039` (unknown-future) stay unchanged.** All non-version fields of the default-path grid are confirmed unchanged (DD #5).

7. **`BeatGridAnchorSource.manual`** is added (`String` raw `"manual"`, closed, non-`CaseIterable`); a unit test pins the raw value + exhaustive 5-case `switch` + bare-string `Codable` round-trip of a `.manual` anchor (both snapped and free-standing). The `BeatGrid.init` `source`-gate DocC is updated to describe `.manual` as a human-asserted bar origin honored as a deliberate user override, distinct from the `.downbeat` dual-gate. `.manual` is coupling-orthogonal (may be snapped or free-standing) (DD #6).

8. **Determinism + total-function no-ops:** non-finite `time` → `self`; `.snapToNearestBeat` on empty `beats` → `self`; `.exactTime` on empty `beats` → a grid with a free-standing manual `gridOrigin` at the clamped time; nearest-beat `argmin` with a **lower-`beatIndex`** tie-break for an exactly-equidistant time; a negative finite `time` under `.snapToNearestBeat` snaps to the earliest beat (DD #7).

9. **Anchor-only mutation (self-vs-result bit-identical) + auto-anchor values unchanged:** the transform changes `gridOrigin` and nothing else — `beats`, `downbeats`, `estimatedTempo`, `confidence`, `tempoAgreement`, `coverage`, `schemaVersion` bit-identical (`Double.bitPattern`/`==`) between `self` and the result; `downbeats` is **not** forced to `.detected`. A test confirms an analyzer-produced (auto) grid still carries a **non-nil** `gridOrigin.beatIndex` satisfying the rebuild invariant (the `Int → Int?` widening did not perturb auto-anchor values — the existing `BeatGridAnalyzerTests` invariant checks, updated for the `if let` unwrap, lock this) (DD #7).

10. **No analysis-path / corpus impact (by construction):** `grep` confirms `repositioningAnchor` is consumer-API-only (not called from `AudioAnalysisService`/`BPMAnalyzer`/`BeatGridAnalyzer`). No `Options` field; no DSP; no re-decode. OA300 (Acc1 ≥ 57/82, Acc2 ≥ 73/82) and GiantSteps (Acc1 ≥ 537/661, Acc2 ≥ 546/661) hold unchanged. Completion Notes state the byte-identity story explicitly: auto-anchor values unchanged + schema-stamp bump only; no `Options`-gated opt-out test exists because there is no default-on pipeline path (DD #7).

## Out of scope (explicit)

- **A demo/UI snap-toggle control** (the click→time mapping, a checkbox for snap on/off). The library ships the value transform + mode enum; the consumer owns the UI. **If a future story bundles UI controls, split per Codex `019f1095` §7: core representation/transform (this story) first, UI snap-toggle second.** This story is the core API only, so it stays one story.
- **Manual BPM / tempo override** — ships as `BeatGridTempoLock.bpm(Double)` (Story 8.9). This is the complementary *anchor* half.
- **Mutating `downbeats`** — the transform sets the bar-origin anchor (provenance `.manual`) but does not synthesize/alter the tri-state `DownbeatResult`. A `.manual` anchor asserts the origin without claiming detection ran.
- **Re-spacing / editing `beats`** (incl. inserting a synthetic beat for an off-beat anchor — the `nil`-index free-standing representation makes that unnecessary), re-running detection, variable-tempo / multi-segment grids.
- **Validating the manual time against track duration** — there is no honest "too large" check without a duration the value type does not hold (Codex `019f1095` §2); the only guards are finite + non-negative clamping.
- **Octave / tempo re-arbitration** (Epic 12) — untouched; the anchor moves on the BPM-stage grid at its octave; `estimatedTempo` is forwarded unchanged.
- **Future reposition modes** (`.nearestDownbeat`, `.nearestBar`) — the enum leaves room (DD #1) but only `.snapToNearestBeat`/`.exactTime` ship here.
