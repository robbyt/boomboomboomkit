A Tier-1 boundary collapse shipped at ZERO accuracy delta.** The sequential `DSP → merge → MetadataCorroborator.apply → EnsembleCombiner` pipeline became a **pool-authoritative two-phase `BPMSelectionPolicy.select`**; `EnsembleCombiner` was deleted, `MetadataCorroborator` relocated into `SignalPool/`, the merge boundary collapsed. Across all 7 stories OA300 stayed 58/82·74/82 and GiantSteps 537/661·546/661 — byte-exact until the deliberate semantic flip, which itself measured zero delta. The single biggest architectural change since Epic 4 moved accuracy by nothing on the default path.

**S2. The byte-inert ÷ semantic split is now a proven, twice-applied pattern.** Story 6.4 split into 6.4a (Float-carrier prep) + 6.4b (EnsembleCombiner removal + git mv) — both byte-inert under a green oracle. Story 6.5 split into 6.5a (rename + type taxonomy, byte-inert) + 6.5b (the genuine semantic flip). Land structure/types under a green byte-equality oracle, then flip semantics ATOMICALLY in a dedicated PR with the byte→semantic test swap in the same commit. **S3. New power for consumers who opt in; zero cost to everyone else.

**S5. ## Key Insights

1. **The byte-inert ÷ semantic split is the project's proven pattern for risky refactors.** Land structure/types under a green byte-equality oracle; flip semantics atomically with the byte→semantic test swap in the same commit. Used twice this epic with zero accuracy delta. Promote to a documented project pattern (Action Item A4).

2. **A green byte-equality floor is a reusable inertness oracle, and retiring it must pair with the semantic change.** The 4 `@Tag` tests proved six structural migrations inert; deleting them early (before the semantic change arrives) would open the exact red interval KDD-A6 forbids.

3. **Output-equivalence is the correct floor once semantics legitimately change.** "Same winner/bpm/confidence outcome," not "same bytes," verified via corpus floors + value-level cross-check + a same-commit oracle. Add this as an explicit team agreement alongside the byte-equality-opt-out backbone (they are complementary, not in tension — byte-equality gates Options-disabled paths; output-equivalence gates the active selection algorithm).

4. **NaN-Hashable is a recurring repo trap with a converged rule.** A `Double.nan` field breaks `Hashable`'s reflexivity (Set double-insert count == 2) and `min/max` clamping does NOT remove NaN — so `isFinite` must be checked BEFORE the clamp, and associated-value enums that cannot carry an init guard must drop `Hashable`.

5. **Architecture-literal API signatures can be non-implementable against the real call graph.** DD #1's 3-arg `select` dropped required cross-window state (`strategy`/`candidateCount`/`votingPolicy`/`votingThreshold`); DD #4's "delete + reimplement" risked the core path. Read the actual call sites before committing to a signature or a deletion — both DR-1 and DR-2 came from doing so at dev-start.

6. **Multiplicative ≠ additive.** `apply`'s ×1.25 boost-and-reselect winner-promotion (`128@0.5 ×1.25 = 0.625 > 140@0.5`) does not survive an additive vote-mass re-expression. Algebraic equivalence must be PROVEN before swapping a transform — Codex's root-hazard catch.

7. **An independent adversary (Codex blind-hunter) earns its slot on novel arithmetic.** Both top-severity defects (hopSize-zero hang, unbounded-weight confidence poisoning) were on surfaces the story newly introduced; the in-house layers cleared the ACs but missed the compounding failure modes. Keep the Codex layer mandatory for stories that add new numeric/weighted behavior.

8. **`deferred-work.md` is the source of truth; story-file checkboxes are not.** When ACs over-claim, reconcile the spec text to the ledger with zero `Sources/` change. The ledger threaded debt forward deliberately across all 7 stories.

9. **Planning docs authored ahead of implementation drift and need a SCHEDULED reconciliation pass.** Epic ACs + architecture.md accumulated factual errors each story corrected locally but no one swept. A dedicated SoT reconciliation must be a named close-out / next-epic-prep task, not piecemeal inline notes (the abandoned `3dd515f` amendment is the cautionary tale).

10. **Substrate-first ordering is genuinely sequential and serializes the epic.** KDD-A6 staging has no internal parallelism; the cost is a long critical path with stacking deferrals, the benefit is each stage lands provably inert. For Epic 7, exploit that 7.1–7.4 (Python-prefix) are explicitly parallelizable to avoid repeating the single-file-of-development cost.
