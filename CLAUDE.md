## Release Process — what ships to `main` vs stays on `develop`

**This repo is multi-branch.** `main` is the public open-source release target; `develop` carries everything else, including all LLM-aided-development tooling. Read this section before authoring or moving any file. **When in doubt, default to develop.**

### Stays on `develop` ONLY — NEVER shipped to `main`

These are the LLM-aided-development scaffolding directories. They MUST be excluded from the squash-merge to main.

- **`CLAUDE.md`** — this file. Public consumers do not need it; shipping it advertises the AI-agent workflow inappropriately and exposes internal conventions
- **`.claude/`** — Claude Code configuration: settings, skills, projects, scheduled tasks, worktrees
- **`.agents/`** — agent skill directory
- **`_bmad/`** — BMAD framework installation: `bmm` module, hooks, config TOMLs, scripts
- **`_bmad-output/`** — every BMAD output:
  - `_bmad-output/implementation-artifacts/` — story specs, regression snapshots, diff-scope proofs, sprint-status.yaml
  - `_bmad-output/ml-training/` — Python training pipeline + Swift CLI fixture extractor + parity harness + reports + `model.pt`
  - `_bmad-output/ml-models/` — uncompiled `.mlmodel` source bundle (the input to `make compile-model`) AND, post-Story-4-6 Branch C, the compiled `giantsteps_v1.mlmodelc/` itself (relocated from `Sources/BoomBoomBoomKitML/Resources/`). Pre-squash-merge to main: VERIFY this directory is NOT in the main-bound diff. The compiled bundle returns to `Sources/` only when a future Branch-A retrain story re-bundles a higher-quality model.
  - `_bmad-output/perf-baselines/` — performance benchmark history
  - `_bmad-output/planning-artifacts/` — epics + architecture docs
  - `_bmad-output/project-context.md` — internal AI-agent context
- **`scripts/`** — non-shipping Python utilities (e.g., `scripts/dawproject-bpm.py` for DAW oracle ground-truth generation)

### Squash-merge protocol (`develop` → `main`)

Manual; the release operator does this by hand. There is no automation.

1. `git checkout main`
2. `git merge --squash develop`
3. **Before committing, `git rm --cached -r` every path in the "Stays on `develop` ONLY" list above**, plus any other develop-only artifact that landed (`*.trace`, etc. — see `.gitignore`)
4. Verify with `git status` that the staged tree contains only paths from the "Ships to `main`" table
5. Commit with a clean public release message — no references to BMAD, Claude Code, party mode, story specs, AI agents, or any LLM-aided-development concept

**`main`'s history must never reflect the LLM-aided development workflow.** No story-spec commit messages. No `Story 4-4b: ...` subjects. The release commit on main is one squash with a public-facing message; the audit trail of *how* the work happened lives on develop.

### Why this matters

- **Consumers cloning from `main`** should see a clean Swift package + a consumer convert tool. Seeing `.claude/`, `_bmad/`, or `CLAUDE.md` would be confusing, would expose internal workflow, and would create an implicit commitment to support development tooling that is project-internal.
- **`develop` is the audit trail.** Story specs, regression evidence, training reproducibility, and AI-agent collaboration history all live there. That's intentional and should remain so.
- **Pre-1.0 framing.** This discipline applies *now*, even pre-1.0; it tightens further at 1.0. Don't let main drift.

### Authoring a new file — decision tree

1. **Does it ship with the library?** → `Sources/` or `Tests/`. Lands on main.
2. **Is it consumer-facing infrastructure** that consumers need at clone time (e.g., a CLI for converting their own ML models)? → `tools/coreml-convert/` (currently the only such directory). Lands on main *only* with explicit story-spec authorization (DD #13 was the precedent — do not add more without one).
3. **Is it project planning, training, ML reproducibility, or AI-agent tooling?** → `_bmad-output/`, `_bmad/`, `.claude/`, `.agents/`, or `scripts/`. Stays on develop.
4. **Anything else?** Default to develop. Ask before promoting.

## Architecture

BoomBoomBoomKit is a standalone audio analysis library for BPM estimation and LUFS loudness measurement. Pure Swift, zero external dependencies — only Apple system frameworks (Accelerate/vDSP, AVFoundation, Foundation). Swift 6.0 strict concurrency, macOS 15+.

### Pipeline

```
PCMBufferReader → fan-out → BPMAnalyzer   (mel-spectrogram onset + autocorrelation)
                           → LUFSAnalyzer  (ITU-R BS.1770-5 K-weighted loudness)
```

All types are stateless structs/enums with static methods. Shared currency type is `[Float]` mono samples.

### Key Types (Sources/BoomBoomBoomKit/)

> Epic 6 added two subdirectories under `Sources/BoomBoomBoomKit/`: `SignalPool/` (unified-signal-pool + ensemble types) and `FeatureSubstrate/` (feature-pipeline substrate — `MLFeatureFrames` + `TensorLayout` relocated here). Those types are grouped at the end of this section.

- **AudioAnalysisService** — Public facade. Composes PCMBufferReader + analyzers. Implements intensity-controlled progressive BPM analysis with configurable merge strategy. Supports cooperative cancellation (via injectable `isCancelled` closure, default `Task.isCancelled`) and per-window progress reporting (via `onProgress` callback). Primary API: `analyzeBPM(url:options:)`.
- **ProgressUpdate** — Public struct (`Sendable`) with `windowsCompleted: Int` and `windowsTotal: Int`. Emitted before each analysis window begins.
- **BPMSelectionPolicy** — Public enum (8 cases): `maxConfidence` (default), `dedup`, `quorum`, `average`, `median`, `weightedAverage`, `union`, `windowVoting`. Controls how candidates from multiple analysis windows are combined. `windowVoting` votes on each window's final disambiguated BPM (post-disambiguation) instead of raw candidates; falls back to `maxConfidence` when no consensus. `windowVoting` is parameterizable via `VotingPolicy` (`.simpleMajority` default; `.confidenceWeighted`, `.thresholdGated` for benchmark sweeps) — see `VotingPolicy.swift`. `CaseIterable` for ablation.
- **VotingPolicy** — Public enum (3 cases): `simpleMajority` (default), `confidenceWeighted`, `thresholdGated`. Resolution policy used ONLY when `mergeStrategy == .windowVoting` (the `BPMSelectionPolicy` value held by `AudioAnalysisService.Options`). It is NOT a `DSPTechnique` (no DSP changes; no ablation matrix expansion) and NOT a new `BPMSelectionPolicy` case (still 8 cases). Future stories must not promote it into either family without explicit story authorization. Threshold (`Options.votingThreshold`, range `[0.0, 1.0]`, silently clamped, NaN/Inf normalize to 0.0) is consulted only by `.thresholdGated`. `CaseIterable, Sendable, Hashable`.
- **AnalysisIntensity** — Public struct (1-10) controlling pipeline depth via `techniqueSet: TechniqueSet`. Named constants: `.fastest` (1), `.default` (7), `.thorough` (8), `.maximum` (10). Levels 1-7 are DSP-only; 8-10 reserved for future ML. Intensity mapping validated by 256-combination ablation matrix (Story 4-7 grew from 128).
- **DSPTechnique** — Public enum (8 cases): `acfSharpening`, `adaptiveThreshold`, `subBandNormalization`, `expandedCandidates`, `fineGridRefinement`, `subBandVoting`, `clickTrackCorrelation`, `superFluxOnset`. Closed set, `CaseIterable`. Story 4-7 added `.superFluxOnset` (Böck & Widmer 2013 frequency-neighborhood max-filter onset detection) — gated by the brutal-corpus gate; case ships available for consumer experimentation regardless of gate outcome.
- **TechniqueSet** — Public struct composing `Set<DSPTechnique>` with named presets: `.baseline` (vote+fine), `.optimal` (sharp+vote+fine, Acc1=67.1%), `.dnbOptimized` (sharp+norm+vote+fine), `.clickAugmented` (optimal + click, opt-in rhythmic-alignment rescoring), `.full` (all 8). `allDSPCombinations()` generates 2^8=256 combos for ablation.
- **MLTechnique** — Public protocol for ML-augmented BPM detection (`Sources/BoomBoomBoomKit/MLTechnique.swift`). Signature `evaluate(trace: BPMDiagnosticTrace) -> MLEvaluation?` is **frozen** at Story 4-5 DD #18 close-out — parameter and return type are stable for the rest of the pre-1.0 window. Library invokes conformers AFTER the DSP pipeline and AFTER metadata corroboration; the result is combined with the DSP result per the user's selected `EnsemblePolicy`, inlined into `AudioAnalysisService.combineEnsemble` (the standalone `EnsembleCombiner` type was removed in Epic 6 / Story 6.4b). The bundled conformance is `BNNSTechnique` in `BoomBoomBoomKitML`; consumers may BYOW via `Options.mlTechnique = MyCustomMLTechnique()`. Backend-agnostic — Core ML, BNNSGraph, MLX, MPS Graph, or pure Swift inference all work. Returning `nil` is the documented abstain path; field expansions on `MLEvaluation` / `EnsembleDecision` require a named story spec.
- **MLEvaluation** — Public struct (`Sendable`) returned by `MLTechnique.evaluate(trace:)`. Three fields: `bpm: Double` (clamped to `60.0...200.0` by conformers), `confidence: Double` (calibrated `[0.0, 1.0]`), `modelIdentifier: String?` (optional stable tag for forensic logs when multiple conformers coexist). Pure value type; no calibration or sanitization is performed at construction. Pre-1.0 caveat per project-context.md: future stories may add fields (e.g., `alternateCandidates`, `featureSummary`) when a downstream consumer surfaces.
- **EnsemblePolicy** — Public enum (`Sendable, Hashable`, 5 cases — NOT `String`/`CaseIterable` since `.weightedVoting` carries an associated value; provides a hand-written `stableKey` + static `allPolicies` instead): `.default` (Epic-6/KDD-A5 balanced-peer ensemble, equivalent to `.weightedVoting(.default)`; invokes ML when a technique is wired up), `.dspOnly` (the ONLY non-ML-invoking case — `MLTechnique.evaluate` operation-inert AND output-inert short-circuited), `.mlOnly` (ML wins when `evaluation != nil`; falls through to DSP otherwise), `.highestConfidence` (winner is whichever side self-reports higher `confidence`, deterministic DSP tiebreak), `.weightedVoting(SignalWeights)` (per-source weighted resolution over the unified pool — `effectiveVote = confidence × weights[source]`, DSP wins ties, emits `EnsembleWeightResolution`). `invokesMLInference` is true for all cases except `.dspOnly`. Carried on `AudioAnalysisService.Options.ensemblePolicy`, which STILL defaults to `.dspOnly` so default-options output is byte-identical. NOT a `DSPTechnique` (no DSP changes, no ablation-matrix expansion); NOT a `BPMSelectionPolicy` case (still 8). The `.dspOnly` byte-identity contract under non-nil `mlTechnique` is test-locked by `EnsemblePolicyTests::dspOnlyDoesNotInvokeMLTechnique` (Story 4-4 AC #14).
- **EnsembleDecision** — Public struct (`Sendable`) emitted on `BPMDiagnosticTrace.ensembleDecision` whenever `MLTechnique.evaluate(trace:)` returned non-nil. Six fields: `policy`, `winner: Winner` (`.dsp` / `.ml` / `.tie` — nested `String, Sendable, Hashable, Codable` enum), `dspConfidence`, `mlConfidence: Double?` (nil only on sentinel-NaN abstain), `mlAbstained: Bool`, `selectedBPM`. Single record that keeps the trace internally consistent when `winner == .ml` and `result.bpm` no longer matches the DSP-derived trace fields. NOT `Hashable` (unsanitized `Double.nan` in DSP/ML values would break the hash invariant); used only as a value carrier, never a `Set`/`Dictionary` key.
- **MLDiagnosticSnapshot** — Public struct (`Sendable, Hashable, CustomStringConvertible`) emitted on `BPMDiagnosticTrace.mlDiagnosticSnapshot` by `MLDiagnosticTechnique` conformers. Six fields: `decodedBPM: Double?`, `softmaxMax: Double?`, `softmaxSecondMax: Double?`, `inputFeatureChecksum: UInt64` (FNV-1a over the post-`vvlogf` log-mel byte stream — Swift/Python parity tripwire), `failureStage: FailureStage?` (nested enum: `featuresAbsent`, `featureVersionMismatch`, `featurizeRejected`, `graphFailed`, `decodeRejected`, `confidenceGateRejected`), `gateFired: Gate?` (sub-discriminator: `gate1Softmax` / `gate2Margin`). Initializer enforces the population matrix via `precondition` (decode fields all-nil or all-non-nil; pre-featurize abstain paths must not construct a snapshot). Survives gate disablement at investigation-time threshold 0.0/0.0 — that's the point.
- **MLDiagnosticTechnique** — Public capability protocol refining `MLTechnique`. Adds `evaluateWithDiagnostic(trace:) -> (evaluation: MLEvaluation?, snapshot: MLDiagnosticSnapshot?)`. Opt-in conformance: `BNNSTechnique` conforms; consumer `MLTechnique` types may opt in. **Cross-target type-narrowing pattern** (Story 4-6 DD #14 project-wide rule): the core `BoomBoomBoomKit` target cannot runtime-narrow via `as? BNNSTechnique` (would create a dependency cycle with `BoomBoomBoomKitML`), so capability protocols declared in core are the canonical resolution. Forwarding wrappers around `BNNSTechnique` lose diagnostics unless they re-conform — wontfix pre-1.0.
- **MLFeatureFrames** — Public struct (`Sendable, CustomStringConvertible, Equatable`) carried on `BPMDiagnosticTrace.mlFeatures`. Eleven fields: `melBands: Int` (128 for the reference architecture), `frames: Int` (pre-resample source frame count), `tensorLayout: TensorLayout`, `logMelData: [Float]` (interpretation depends on `tensorLayout`), `sampleRate: Double`, `fftSize: Int`, `hopSize: Int`, `melFmin: Double`, `melFmax: Double`, `logCompressionScale: Float`, `featureSetVersion: String` (drift-detection seam — `"v1"` since Story 4-5; any change to `BPMAnalyzer` mel/FFT/log parameters MUST bump). Throwing-init invariants: `count == melBands * frames`, both dimensions positive, total ≤ `8_388_608` floats (≈ 32 MB guard). Surfaces the raw model input so consumers can audit what the ML conformance actually saw.
- **TensorLayout** — Public enum (`String, Sendable, Hashable, CaseIterable`, 2 cases): `.frameMajorLogMel` (the on-the-wire shape `BPMAnalyzer` actually emits — `[frame * melBands + mel]` ordering), `.nchw` (reserved for future producers emitting mel-major bytes). **Tag, not a constraint** — the init cannot inspect `logMelData` to verify; mislabeled payloads silently transpose at the consumer. `BNNSTechnique` transposes frame-major → mel-major at evaluate time. Pre-1.0 — Story 4.6+ may extend the case list (e.g., `.nhwc`).
- **MLTechniqueError** — Public enum (`Error, Sendable`, 5 cases): `.modelResourceMissing(URL)` (bundle/path lookup failed), `.modelLoadFailed(underlying: any Error)` (BNNSGraph compile returned empty), `.invalidTensorContract(missing: String)` (input/output argument resolution failed), `.binCountMismatch(expected: Int, actual: Int)` (BNNS expects 256 bins → `bpm = 30.0 + Double(argmax)`), `.invalidFeatureShape(reason: String)` (MLFeatureFrames throwing-init invariant violation). Thrown only at construction time (`BNNSTechnique.init(modelURL:) throws` and `MLFeatureFrames.init(...) throws`); `MLTechnique.evaluate(trace:)` itself never throws — the abstain path is `nil`.
- **BPMDiagnosticTrace** — Public struct (`Sendable`) capturing per-step pipeline intermediate state. Populated when `Options.enableTrace == true` (DSP fields) and/or `Options.enableMLDiagnostics == true` (ML fields — separate gate per Story 4-6 P17). Carries the typed-evidence structs below plus per-step numeric scalars; Epic 6 added `signalParticipationTrace: [SignalParticipationTraceEntry]` (per-signal unified-pool participation log) and `ensembleWeightResolution: EnsembleWeightResolution?` (KDD-A5 weighted-ensemble winner record). Evolving API per pre-1.0 framing — every field change must pass the five `bpm-diagnostic-trace` skill audit recipes (zero matches against `Sources/` and `Tests/`).
- **ClickCorrelationEntry** — Public typed-evidence struct (`Sendable, CustomStringConvertible`) on `BPMDiagnosticTrace.clickCorrelationDetail`. Three fields: `candidateIndex: Int`, `bpm: Double` (full precision), `normalizedClickScore: Float` (`[0, 1]`). Replaces the pre-Story-3-3b `[String: Float]` keyed by `%.1f` BPM, which silently collapsed candidates whose BPMs rounded to the same one-decimal label.
- **HarmonicRatioEvidence** — Public typed-evidence struct (`Sendable, CustomStringConvertible`) on `BPMDiagnosticTrace.harmonicRatioEvidence`. Four fields: `ratio: String` (`"2:1"`, `"3:2"`, or `"3:1"`), `fastBPM`, `slowBPM`, `winnerBPM`. Replaces a `[String: String]` shape; preserves `Double` precision and surfaces typed access. Story 3-1's octave disambiguation source-of-truth.
- **SubBandVoteEvidence** — Public typed-evidence struct (`Sendable, CustomStringConvertible`) on `BPMDiagnosticTrace.subBandVoteEvidence`. Three fields: `preVoteBPM: Double`, `postVoteBPM: Double`, `changed: Bool`. Records Step 10b sub-band-voting outcome.
- **DurationHintEvidence** — Public typed-evidence struct (`Sendable, CustomStringConvertible`) on `BPMDiagnosticTrace.durationHintEvidence`. Three fields: `fileDurationSeconds: Double`, `barCandidates: [BarCandidate]`, `boostedCandidates: [Double]`. Step 9.7 diagnostic record (Story 3-4 duration-derived BPM hint).
- **BarCandidate** — Public typed-evidence struct (`Sendable, CustomStringConvertible`) used inside `DurationHintEvidence.barCandidates`. Two fields: `bars: Int` (drawn from `BPMAnalyzer.durationHintBarCounts = [32, 64, 96, 128, 192, 256]`), `bpm: Double` (derived from `bars * 4` beats / `fileDurationSeconds`, filtered to 60-200 BPM).
- **SubBandEnergies** — Public typed-evidence struct (`Sendable, CustomStringConvertible, Equatable`) on `BPMDiagnosticTrace.subBandEnergies`. Four `Float` fields: `kick`, `snare`, `crack`, `hihat`. Static `.zero` default emitted when sub-band computation was skipped (intensity 1-2, or `.subBandVoting` not in the active set). Replaces the legacy `[String: Float]` keyed by the closed `{"kick","snare","crack","hihat"}` set — the last surviving instance of project-context.md §"Banned trace-field shapes" anti-pattern (1) that Story 3-3b cleaned up.
- **BNNSTechnique** — Public struct (`@unchecked Sendable`) in `Sources/BoomBoomBoomKitML/`, `@available(macOS 15.0, *)`. Default `MLTechnique` implementation backed by Apple's BNNSGraph CPU-only inference path. Conforms to `MLDiagnosticTechnique`. Three-stage pipeline: `featurize(_:)` (transpose frame-major → mel-major, z-score normalize per mel band, resample to fixed `W=512`), `inferTempoCNN(_:)` (compiled BNNSGraph against `[1, 1, 128, 512]` NCHW input with host-side softmax), `decode(_:)` (256-bin argmax → `bpm = 30.0 + Double(argmax)`). **No bundled model ships** since Story 4-6 Branch C — consumers BYOW via `init(modelURL: URL) throws`.
- **CoreMLTechnique** — Public struct (`Sendable`) in `Sources/BoomBoomBoomKitML/`. **Intentional non-conforming placeholder** — does NOT adopt `MLTechnique` and cannot be assigned to `Options.mlTechnique`. Retained so `Bundle.module` symbol resolution + the public-API surface of the ML target stay stable; consumer ML augmentation today goes through `BNNSTechnique`. Re-introducing a CoreML-backed `MLTechnique` is a future-epic concern with no scheduled story.
- **BPMAnalyzer** — DSP pipeline with technique-gated stages: 9 unconditional steps (energy scan → silence check → mel-spectrogram onset (with optional sub-band normalization) → adaptive thresholding → autocorrelation (with optional ACF sharpening) → Fourier tempogram → periodicity fusion → peak selection → range normalization 60-200 BPM) plus 2 optional gated rescore stages (step 9b click-track cross-correlation, step 9.7 duration-derived BPM hint) plus 3 post-disambiguation steps (step 10 sub-band voting → step 10b sub-band peak confirmation → step 10c fine-grid refinement). Step identifiers are stable per project-context.md "Pipeline step numbers are stable identifiers". Internal type (not public). Uses three internal buffer structs (`PipelineBuffers`, `ACFBuffers`, `TempogramBuffers`) following ADR-3 allocate/deallocate pattern to avoid per-step heap allocations. All buffer lifetimes are scoped to a single `estimateBPM()` invocation.
- **MelFilterbank** — Caseless enum namespace for Hz↔mel conversion and triangular filterbank matrix construction. Used by BPMAnalyzer.
- **LUFSAnalyzer** — ITU-R BS.1770-5 integrated loudness. K-weighting via vDSP.Biquad (Double precision). Pre-computed coefficients for 44.1/48/96kHz only. Internal type.
- **PCMBufferReader** — Reads audio files (WAV, AIFF, MP3, FLAC, M4A, CAF) into mono `[Float]` via AVFoundation. OGG/Vorbis is NOT supported (no Core Audio codec). Supports partial reads and downsampling.
- **MetadataPolicy** — Public struct (`Sendable, Hashable`) configuring file-tag BPM corroboration (Story 3.6). Fields: `enabledSources: Set<MetadataSource>` (default all three), `consensusTolerance` (0.5 BPM absolute), `corroborationTolerance` (0.03 relative), `corroborationBoost` (1.25), `maxBoostedConfidence` (0.95), `skepticismPenalty` (0.85), `allowOctaveCorroboration` (true), `allowTripletCorroboration` (false — gated until validated by follow-up story), `valueRange` (30.0...300.0), `parsing: ParsingOptions`. Two presets: `.default` (all sources on) and `.disabled` (empty `enabledSources`, fully suppresses I/O and merge-stage boost — byte-identical pre-Story-3.6 behavior).
- **MetadataSource** — Public enum (`String, CaseIterable, Sendable, Hashable`, 3 cases): `.iTunesTmpo` (MP4/M4A `tmpo` atom), `.id3TBPM` (ID3v2 `TBPM` text frame in MP3 and AIFF `ID3 ` chunks), `.vorbisBPM` (FLAC Vorbis `BPM=` comment, case-insensitive). Closed set; AVFoundation is never consulted for metadata (deprecated/async-only on macOS 13+).
- **MetadataBPMEvidence** — Public struct (`Sendable`) emitted on `AudioAnalysisResult.metadataEvidence` for every parsed tag. Fields: `source`, `rawValue`, `parsedBPM` (NaN for parse-phase rejections), `corroboratedWith: Double?`, `ratioMatched: HarmonicRatio?`, `boostApplied: Double`, `rejectionReason: String?` (parse-phase: `sentinel-zero`, `out-of-range`, `non-numeric`; decision-phase: `intra-file-conflict`, `dsp-disagreement`, `uncorroborated-single-tag`).
- **HarmonicRatio** — Public enum (`Sendable, Hashable`, 5 cases): `.one` (same-tempo placeholder; never set in evidence — `nil` represents same-tempo), `.double`, `.half` (octave), `.threeHalf`, `.twoThird` (triplet, gated). Story 3.1 detects 3:2 / 3:1 in `BPMAnalyzer.resolveOctaveAmbiguity` as trace-only evidence; Story 3.6 introduces the first metadata-driven *winner-promotion* via these ratios.
- **FileMetadataReader** — Internal caseless enum namespace. Direct container parsing for embedded BPM tags: MP4 atom walker, ID3v2.3/v2.4 frame walker (MP3 + AIFF/AIFC `ID3 ` chunk), FLAC Vorbis comment parser. Never throws — metadata absence is not an error. Bounds-checked, FileHandle-defer-closed.
- **MetadataCorroborator** — Internal caseless enum namespace (relocated to `Sources/BoomBoomBoomKit/SignalPool/` in Epic 6). `apply(to:input:)` runs AFTER `BPMSelectionPolicy.merge` returns (it is Phase 2a of `BPMSelectionPolicy.select`, now threaded with `metadataScale = SignalWeights.fileMetadata`, default 1.0): boosts every candidate matching any participating tag, re-selects the winner from the boosted pool (allows tag-driven winner-promotion), and applies confidence boost (×1.25 clamp 0.95) or skepticism penalty (×0.85). Lives outside `merge` to keep that signature stable across 41 call sites and to ensure single-window paths (intensity 1-5) still apply corroboration. The internal `MetadataCorroborationInput` struct (also in this file) carries the consensus signal from the service to `apply`.

Epic 6 unified-signal-pool + ensemble types (`Sources/BoomBoomBoomKit/SignalPool/` + root):

- **BPMSelectionPolicy.select(from:)** — Pool-authoritative two-phase selection (Epic 6 / KDD-A6 Stage 3). Phase 1 = cross-window `merge` (verbatim; the frozen 41-call-site signature is unchanged, still driving the 8-strategy aggregation). Phase 2a = multiplicative metadata corroboration (`MetadataCorroborator.apply`, threaded with `metadataScale = SignalWeights.fileMetadata`; default 1.0 byte-reproduces). Returns `PoolSelection?` — empty pool → `nil` (W61 Optional path, not a precondition crash). Phase 2b (ML fusion + KDD-A5 weighted resolution) stays in `AudioAnalysisService.combineEnsemble` (DR-1). With `Options.ensemblePolicy == .dspOnly` (default) the path is byte-identical.
- **UnifiedSignalPool** — Internal struct (`Sendable`), the authoritative selection input. Fields: `dspWindows: [BPMResult]`, `metadataInput: MetadataCorroborationInput`, `candidateCount: Int`, `mlParticipation: SignalParticipation`, `weight: Double`. Built unconditionally. NOT public.
- **SignalWeights** — Public struct (`Sendable, Hashable`). Per-source weight carrier parameterizing `EnsemblePolicy.weightedVoting`: `dsp`, `ml`, `fileMetadata`, `beatGrid: Double` (finite-normalizing init, isFinite-first, non-negative multipliers — `Hashable` kept because NaN is unreachable post-init). `.default` = equal weighting. `fileMetadata` also scales Phase-2a corroboration strength.
- **SignalSource** — Public enum (`String, CaseIterable, Sendable, Hashable, Codable`, 4 cases, closed set): `.dsp`, `.ml`, `.fileMetadata`, `.beatGrid` (no producer until Epic 8 — deferred-work W53).
- **OctaveEquivalencePolicy** — Public enum (`String, CaseIterable, Sendable, Hashable`, 3 cases, closed set): `.collapseToFundamental`, `.octaveAwareWithPenalty` (`.default`), `.exactMatchOnly` (KDD-A1, Story 6.5a). `allCases.count == 3` unit-test-locked (`EnsembleConfigTypesTests`). Configurable-but-reserved — octave behavior is still governed by `MetadataPolicy` (6.5b accepted-but-reserved the param).
- **MLExecutionPolicy** — Public enum (`Sendable, Equatable`, 3 cases): `.never`, `.always`, `.whenDSPConfidenceBelow(Double)` (default `0.85`). Drops `Hashable` (assoc-value Double can be NaN — `EnsembleDecision` precedent). **Declared-but-not-yet-`Options`-wired** (forward-declared surface, Story 6.5a).

## Design Constraints

- All DSP uses Apple's Accelerate (vDSP) — no manual loops for bulk numeric operations
- K-weighting filters use Double precision throughout (Float causes measurable errors near unit circle poles)
- `BPMResult` and `LUFSResult` are internal; key public types include `AudioAnalysisResult`, `AnalysisIntensity`, `DSPTechnique`, `TechniqueSet`, `BPMSelectionPolicy`, `VotingPolicy`, `MLTechnique`, `EnsemblePolicy`, `SignalWeights`, `BPMDiagnosticTrace`, and `ProgressUpdate` — see the `### Key Types` roster for the full public surface (it now includes the Epic-6 pool/ensemble + FeatureSubstrate types)
- Default intensity mapping uses `.optimal` preset (sharp+vote+fine) with `maxConfidence` merge — validated by ablation on OA300 corpus. Regression floors: Acc1 ≥ 57/82 (69.5%), Acc2 ≥ 73/82 (89.0%). Current measurement (Story 5-5 2026-05-21): Acc1 = 58/82 (70.7%), Acc2 = 74/82 (90.2%)
- `@preconcurrency import AVFoundation` is used in PCMBufferReader for Swift 6 concurrency compatibility
- `nonisolated(unsafe)` in PCMBufferReader.downsample is intentional — AVAudioConverter calls its block synchronously
